1. このアプリについて

山や公園での運用ログを、スマホ 1 台で、その場で書くためのアプリです。ログは FLE(Fast Log Entry)という短い書き方で、40m cw の次に 0230 ja1abc、その次は 35 ja2xyz のように、前の行と同じところは省いて書けます。電波のない山頂でも書け、帰ってから SOTA・POTA・WWFF・HAMLOG のファイルを一度に作れます。

できること

書くFLE の書き方で 1 行に 1 QSO。ログ欄の下の候補バーに、省いた時刻・バンド・モード・RST を補った結果が出ます。スマホでは、FLE を打つのに必要なキーだけを並べた、画面上のキーボード(フルキー)で打ちます
電波がなくても一度開いておけば、電波がなくても書けます。ログは端末に自動で保存されます
準備する行き先を「予定」に登録しておき、当日は選ぶだけ。山頂の地図で、アクティベーションゾーン・市区町村(JCC・JCG)・POTA の公園を確かめられます
PC と同期する設定と予定を、PC とスマホで同期できます
ファイルを作るSOTA の CSV、POTA・WWFF・SOTA の ADIF、HAMLOG の CSV を、zip で一度に作ります。ほかのログソフトの ADIF を、ログに足すこともできます

できないこと・注意

  • ログの本文は同期しません。スマホで書いたログは、スマホの中だけにあります。
  • SOTA・POTA などのサイトへの送信はしません。作ったファイルを、各サイトに自分で取り込みます。
  • 山・公園の候補の検索、JCC・JCG の照会、同期には、電波が必要です。

2. 初期設定(最初に一度だけ)

ホーム画面に追加する

電波のない山頂でも使えるよう、電波のあるところで一度開いて、ホーム画面に追加します。

  • iPhone: Safari で https://fleonline.sotalive.net/ を開き、共有ボタン →「ホーム画面に追加」。
  • Android: Chrome のメニュー →「ホーム画面に追加」(またはこのアプリのメニューの「ホーム画面に追加」)。

以後は、ホーム画面のアイコンから開きます。iPhone では、Safari とホーム画面のアプリとで、データが別々に保存されます。ログ・設定・予定は、ホーム画面のアプリで使ってください。

最初に決める設定

画面右上の歯車が設定です。ほとんどは最初の値のままで使えます。次の 3 つだけは、最初に確かめてください(すべての設定は「設定」を見てください)。

タイムゾーンログの時刻を、どのタイムゾーン(時間帯)で書くか。最初は UTC です。日本時間で書くなら JST にします。UTC 以外にすると、ログの先頭に timezone の行が入ります
よく使うリグ1 行に 1 つ(例: KX2+EFHW)。ログで rig と打つと候補に出ます。HAMLOG を使うなら、HAMLOG で定義した名前を書きます
HAMLOG の時刻・出力HAMLOG を使うときだけ。CSV の時刻を JST(J。最初の値)と UTC(U)のどちらで書くか、QTH・Rmks1・Rmks2 に何を書くか

PC も使うなら

予定の登録などは、PC の大きな画面の方が楽です。PC で入れた設定と予定は、同期でスマホに写せます。スマホだけでも、すべての操作ができます。

3. 前日: 準備する

ここでは、ふつうの SOTA アクティベーションを例にします。POTA・WWFF で違うところは、そのつど書きます。

予定を登録する

メニュー(「…」)→「予定」→「予定を追加」で、行き先を登録します。

名前例: 陣馬山 10/25(自分用の名前)
日付任意。運用の日
自局コールサイン(例: JL1NIE/1)
SOTA / POTA / WWFF名前や番号を打つと候補が出ます(陣馬、KN-02 など)。選ぶだけです
グリッド任意。「現在地」ボタンでも入ります
リグ・QSL メッセージ任意。リグは HAMLOG の Rig= に入ります。QSL メッセージには $mysota や $rig が使えます
メモ任意。JCC・JCG など。山・公園を選ぶと、電波があれば調べて入ります

POTA: 公園が重なるところでは、POTA の欄に公園を並べます(JP-1151 JP-1164)。

山頂の地図で確かめる

予定の SOTA 欄の横にある「地図」で、山頂のアクティベーションゾーン、市区町村の境、市区町村ごとに該当する POTA の公園を見られます。都県境の山では、どちら側で運用するか(メモに書く JCC・JCG と、POTA の公園)を、ここで決めておきます。詳しくは「山頂の地図」を見てください。

出発前に確かめる

  • 地図が端末に保存されたか: 予定に入れた山頂の地図は、電波のあるうちに自動で保存されます。予定の一覧に「地図: 保存済み」と出ていれば、山頂で電波がなくても見られます。「まだ保存していません」なら、電波のあるところでアプリを開いてください。
  • PC で予定を入れたなら: スマホのアプリを電波のあるところで開き、予定が入ったかを見ます(同期は、開いたときに行います)。
  • ホーム画面から開けることを確かめておくと安心です。

4. 当日: ログを書く

新しいログを始める

  1. メニュー →「新しいログ」。自局のコールサインは、前に入れたものが入っています。
  2. 「予定から選ぶ」で今日の予定を押すと、自局・山・グリッド・メモなどが入ります。
  3. 必要なら、バンド(または周波数)とモードも入れます。
  4. 「ログに書き込む」を押すと、いま書いていたログが、次のような行で始まる新しいログに置き換わります。
mycall JL1NIE/1
mysota JA/KN-028
date 2026-10-25
rig KX2+EFHW
qslmsg $mysota $rig
# JCC#111001 相模原市緑区
40m cw

置き換える前のログは、メニューの「元に戻す」で戻せます。# で始まる行はメモ(JCC・JCG など)で、出力のファイルには入りません。予定を使わずに、その場で自局や山を入れてもかまいません。

アクティベーションゾーンの中か確かめる

QSO を始める前に、メニュー →「山頂の地図」を開きます。現在地(GPS)がアクティベーションゾーンの中にあるか、どの市区町村にいるか(メモに書く JCC・JCG)、どの公園の中にいるかが出ます。陣馬山のように都県境にある山では、どちら側にいるかもここで確かめます。

QSO を書く

1 行に 1 QSO ずつ書きます。

40m cw
0230 ja1abc
35 ja2xyz 579
41 jr1qrp/1 st-012
ssb
52 ja3pqr
  • 0230 ja1abc: 02:30 に JA1ABC。時の桁は前の行から引き継ぐので、次からは分だけ(35 → 02:35)で書けます。
  • 時刻は自動で入ります(設定「時刻を自動で入れる」。最初はオン)。時刻を書かずにコールサインだけ打って OK を押すと、その行の最初の 1 文字を打った時刻が入ります。
  • 579: 送ったレポート。省くと、モードの標準(CW 599 / SSB 59)になります。
  • st-012: 相手が山にいる(S2S)。自分の山と同じアソシエーション(ja/)は省けます。相手の公園(jp-1234、P2P)も同じように書きます。
  • バンド・モードは、書き換えるまで続きます(ssb、20m ssb)。

書き方のすべては「FLE の書き方」を見てください。

確定して次の行へ(OK)

ログ欄の下の候補バーが緑になったら、その行は QSO として読めています。右端の ✓ OK を押すと、時刻などを書き足して、次の行へ進みます。

  • QSO は、OK を押さなくても、正しく書けた時点でログに入っています。ただし、時刻を書いていない行は、前の行の時刻になります。いまの時刻を入れるには OK を押します。
  • キーボードの ↵ は改行するだけで、時刻は書きません。
  • 候補バーが橙なら入力の途中、赤なら直す必要があります(「画面の見かた」)。

その場で直す

レポートやコールサインを言い直されたら、候補バーの直したい要素(コール・RST・時刻)を押します。ログ欄のカーソルがその要素の末尾へ移るので、⌫ で消して打ち直します。RST は、1 回押すともらったレポートへ、もう 1 回押すと送ったレポートへ移ります。⌫ で消しすぎたときは、キーボードの ↶ で戻せます。詳しくは「QSO を直す」を見てください。

QSO の数を見る

候補バーの左の数が、その日の QSO の数です。下の小さい数は、アクティベーションの成立に必要な QSO の数(SOTA は /4、POTA は /10)で、その数に届くと緑になります。

場所を移るとき

別の山・公園へ移ったら、新しい場所で最初の QSO を書く行にカーソルを置き、メニュー →「場所の変更」を開きます。その行から先の QSO の場所が変わります(同じログのままです)。

0 時をまたぐとき

時刻を自動で入れているときに日付が変わると、OK を押したときに day + の行が自動で入り、画面の下に通知が出ます。

時刻を手で打っているときは、前の QSO が 21 時以降で、この行の時刻が 3 時より前の場合(2358 のあとの 0002 など)に、OK で day + が入り、ログの上に「newday です」と約 3 秒出ます。

どちらも、出ている間に「元に戻す」を押すと取り消せます。

ほかのアクティベーション局を呼びまわるとき

山頂から、ほかの山・公園で運用している局を呼びまわる(S2S・P2P)ときは、ja1abc tk-001 のように、相手の山・公園も書きます。

相手の山・公園を書いた行は、その行を打ち始めた時刻ではなく、OK を押した時刻が入ります。相手を聞いて書き始めてから、順番を待って呼ぶので、打ち始めの時刻だと、実際の交信と大きくずれることがあるためです(設定「チェイス・S2S・P2P の行は、OK を押した時刻にする」。最初はオン)。

CQ を出していて S2S の局に呼ばれた行も、相手の山を書くので OK を押した時刻になります。この場合は交信が短いので、ずれは小さく済みます。

5. 終わってから: ファイルを作る

  1. メニュー →「書き出し (ADIF等)」。
  2. 日付・自局・運用場所が足りないときは、確認の画面が出ます。「ログに書き込んで生成」で足りない項目を書き込んでから作るか、「このまま生成」を選びます(グリッドは任意なので、なくても出ません)。
  3. zip ファイルがダウンロードされます。

zip の中のファイルを、それぞれのサイト・ソフトに取り込みます。

sotaYYYYMMDD.csvSOTA のデータベースに取り込む
コールサイン@公園-日付.adiPOTA のサイトに取り込む(公園ごと)。WWFF・SOTA の ADIF も同じ形です
hamlog-….csvHAMLOG に取り込む

ファイルの中身は「書き出すファイル」を見てください。誤りのある行があるときは、ファイルは作られず、誤りを書いたテキストだけが出ます。直してから、もう一度書き出します。

FLE ログを保存する

FLE のログそのものは、メニュー →「FLEログを保存」でテキストファイルにできます。あとで「FLEログを開く」で読み込めます。

ほかのログソフトの ADIF を足す

同じ運用の一部を別のログソフトで記録したときは、メニュー →「ADIFを追加」で、その ADIF を FLE の行にしてログの末尾に足せます。足す前のログは「元に戻す」で戻せます。

時間帯を間違えたとき

JST で書いたのに設定が UTC だったときなどは、設定のタイムゾーンを変えます。QSO のあるログでは、変換する(同じ瞬間の新しい時間帯の時刻に書き直す)か、時刻はそのまま(timezone の行だけを書き換える)かを聞きます。JST で書いたのに timezone を書き忘れたときは「時刻はそのまま」です。

6. リファレンス

画面の見かた

ログ欄の下の候補バーに、カーソルのある行の解釈が出ます。色で状態がわかります。

橙入力の途中です。コールサインなどが、まだ確定できる形ではありません。手を止めると、足りないものが出ます。
緑解釈できました。時刻・バンド・モード・レポートを補った結果が出ます。右端の ✓ OK で、時刻などを書き足して次の行へ進みます。最後の行なら新しい行を足し、ログの途中なら次の行へ移るだけです(行は増えません)。コール・RST・時刻を押すと、ログ欄のその要素の末尾へカーソルが移ります(「QSO を直す」)。
赤バンドやモードの書き忘れなど、直す必要があります。
(空の行)いまの時刻と、その行の時点のバンド・モードが出ます。次の QSO には、この値が入ります。
(指令の行)行からは見えない値が出ます。day + なら進んだ先の日付(曜日つき)、mysota などなら山・公園の名前(電波があるとき)、qslmsg なら変数を置き換えた文面、rig ならリグ(rig - なら「リグなし」)。
  • QSO の数: 候補バーの左に、カーソルのある日(UTC の日付)の QSO の数を大きく、全体の数を小さく出します。SOTA・POTA の運用では、小さい数はアクティベーションの成立に必要な QSO の数(SOTA /4、POTA /10)になり、その数に届くと緑になります。誤りのある行があると赤になり、⚠2 のように誤りの数も出ます。設定の「QSO の数」で、全体の数だけにもできます。
  • 時刻と運用先: ログ欄の上に、時刻と、自局のコールサイン、カーソルの行で有効な山・WWFF・公園を大きく出します。その下には、カーソルの行で有効なメモ(それより前で最後の # の行)を出します。時刻は、ログに入る時刻と同じタイムゾーンで出し、UTC でなければ UTC も添えます。画面が狭くて入らないとき(OS のキーボードを出したときなど)は出ません。
  • 補完候補: 打っている途中で、キーワード・バンド・モードなどの候補が候補バーに重ねて出ます。押すと入ります。
  • ログは下に寄せて表示し、打っている行が候補バーのすぐ上に来ます。
  • スマホを横向きにすると「縦向きにしてお使いください」と出ます(ログはそのまま)。

スマホのキーボード(フルキー)

スマホなど、タッチ操作の端末では、OS のキーボードの代わりに、FLE を打つのに必要なキーだけを並べた、画面上のキーボード(フルキー)が出ます。かな入力から英数字へ切り替える手間がありません。

      10:05:12 JST  UTC 01:05
       JA1ABC  JA/KN-028
│ 1111 jj0pic         │
│ 2107 ja1xyz 7▌      │ (打っている行)
[3/10][JA1XYZ 579/599   ][✓]
[1][2][3][4][5][6][7][8][9][0]
[Q][W][E][R][T][Y][U][I][O][P]
[A][S][D][F][G][H][J][K][L][-]
[↑][Z][X][C][V][B][N][M][/][⌫]
[🌐][↶][←][            ][→][ ↵ ]
  • ログ欄をタップしても、OS のキーボードは出ません(カーソルは出ます)。
  • 英字はログに小文字で入ります(FLE は大文字・小文字を区別しません)。- は L の右、/ は M の右です。
  • 続けて 2 回押すと、別の文字になります。/ を 2 回で .(7.0295 のような周波数に)、- を 2 回で ,。キーの右下に小さく出ています。
  • 長押し(0.5 秒ほど)で、別の記号が入ります。3 は #(メモの行や JCC# に)、0 は +(day + に)、7 は ?(聞き取れなかった文字に。JA1AB? のように打っておくと、書き出しの前に知らせます)。押している間の吹き出しが記号に変わり、離すと入ります。
  • Z の左は Caps(↑)です。押すと ↑ が塗りつぶしになり、英字が大文字で入ります。小文字の m と n を見分けにくいときに便利です。この状態は端末ごとに覚えます。
  • 下の段のいちばん広いキーが空白、右下が ↵ です(文字は書いていません)。
  • ↵ は改行するだけで、確定はしません(時刻などは書きません)。行の途中なら、そこで行が割れます。ログの途中で押せば、間に QSO を足せます。確定は候補バーの ✓ OK です。
  • ↶ は、直前の編集を取り消します(「取り消しと「元に戻す」」)。
  • ⌫ は、押し続けると続けて消します。
  • 空白キーか ← → キーの上で左右になぞると、カーソルが 1 文字ずつ動きます(「なぞってカーソルを動かす」)。
  • キーの高さは、キーボードの上の縁のつまみを上下にドラッグして変えられます(キーが正方形になる高さから、その 1.5 倍まで)。手袋をしているときなどに便利です。端末ごとに覚えます。
  • 日本語(<山田さん> のようなメッセージや、qslmsg)は、🌐 で OS のキーボードに切り替えて打ちます。終わったら、下に出る「フルキーに戻る」を押します。
  • 「新しいログ」「場所の変更」「予定」などの画面でも、自局・SOTA・POTA・WWFF・グリッド・メモの欄は、同じキーボードで打ちます(英字は最初から大文字)。↵ で次の欄へ進みます。メモに日本語(市区町村名など)を書くときは、🌐 で OS のキーボードに切り替えます。予定の名前は、はじめから OS のキーボードです。

PC で使うとき

PC では、物理キーボードで打ちます(フルキーは出ません)。スマホとの違いは次のとおりです。

  • Ctrl+Z(Mac は ⌘Z)で、直前の編集を取り消します。フルキーの ↶ と同じ取り消し方です。
  • 補完候補は、ログ欄の下端に重ねて出ます。
  • 候補バーの左の QSO の数をクリックすると、QSO と誤りの一覧が出ます。誤りをクリックすると、その行へ移ります(スマホでは、メニュー →「QSO一覧」)。
  • 設定の「数字キーの行」をオンにすると、ログ欄の下に数字のキーが出ます(コールサインの数字や / - が打ちやすくなります)。左右になぞると、カーソルが動きます。
  • 確定のときに RST を書くかは、PC とスマホで別に設定します(PC は最初から書き、スマホは最初は書きません)。

QSO を直す

候補バーの、直したい要素を押します。ログ欄のカーソルが、その要素の末尾へ移るので、⌫ で末尾から消して打ち直します(選択はしないので、打っても他の文字は消えません)。

押すところカーソルの移り先(|)
コール1005 ja1xyz| 57 599
RST(1 回目)1005 ja1xyz 57 599| もらったレポート(言い直してくるのは、たいていこちら)
RST(続けてもう 1 回)1005 ja1xyz 57| 599 送ったレポート
時刻1005| ja1xyz 57 599
  • 例: もらったレポートが 599 ではなく 579 だった → RST を押す → ⌫ ⌫ → 79。
  • 例: JA1XYZ ではなく JA1XYW だった → コールを押す → ⌫ → w。
  • 省いて書いた RST や時刻(バーには補った値が出ています)を押すと、その値を行に書き込んでから末尾へ移ります。ja1xyz の行で RST を押すと ja1xyz 599 599| になります。
  • 途中の文字は、要素を押して末尾へ移ってから、なぞってカーソルを合わせます。
  • 前の QSO を直すときは、ログ欄でその行をタップします。その行が候補バーに出るので、同じように直せます。
  • 要素を押しても、次の行へは進みません。

なぞってカーソルを動かす

指で文字と文字の間を狙わなくても、カーソルを 1 文字ずつ動かせます。date・mysota・qslmsg などの QSO でない行は、候補バーで要素を選べないので、これが直し方の中心になります。

  1. スマホでは空白キーか ← → キーに、PC では数字の行に、指を置きます。
  2. 指を離さずに、左右へなぞります。約 20px ごとに 1 文字、なぞった向きへカーソルが動きます。行や要素を越えても動きます。
  3. 指を離すと止まります。なぞったときは、指を置いたキーの文字(空白・数字)は入りません。
  • 1 文字だけなら、← → を押しても動きます。
  • 例: mypota jp-1151 jp-1164 の 1151 を 1152 にする → 1151 のあたりをタップ → なぞって 1151| に合わせる → ⌫ → 2。
  • 例: 送ったレポート 559 の真ん中の 5 を 7 にする → RST を 2 回押して 559| → 左へ 1 文字分なぞって 55|9 → ⌫ → 7。
  • だいたいの位置へはログ欄をタップし、細かい位置合わせをなぞりで行うと楽です。

取り消しと「元に戻す」

↶ / Ctrl+Z直前の編集を取り消します。⌫ で続けて消した分は、1 回で、消し始める前の状態に戻ります(前の行まで消していても)。続けて打った分は、1 回で 1 行分ずつ戻ります。押すたびに、さらに前へ戻ります。OK や候補で書き換えた分も戻せます
通知の「元に戻す」「すべて消す」「新しいログ」「FLEログを開く」「サンプル」「ADIFを追加」、時刻の変換などのあと、画面の下に出る通知から、その前のログに戻せます(約 8 秒)。OK で day + などを入れたときも出ます
メニューの「元に戻す」ログを丸ごと置き換える前の内容を 1 つだけ覚えていて、あとからでも戻せます

予定

メニュー →「予定」。行き先を 50 件まで登録できます。項目は「前日: 準備する」の表のとおりです。

  • 「新しいログ」「場所の変更」の画面の「予定から選ぶ」で使います。予定の自局・山・公園・グリッド・メモが欄に入り、書き込むと、予定の日付・リグ・QSL メッセージも指令の行になります(ログにすでに同じ行があれば書きません)。
  • 予定に入れた山頂の地図は、電波のあるうちに自動で端末に保存されます。一覧に「地図: 保存済み」か「まだ保存していません」が出ます。
  • 予定は同期の対象です。

場所の画面とメモ

「新しいログ」と「場所の変更」で開く画面です。自局のコールサイン・SOTA・POTA・WWFF・グリッド・メモを入れて「ログに書き込む」と、指令の行(mycall・mysota など)を書きます。

  • SOTA・POTA・WWFF は、名前や番号を打つと候補が出ます(電波が要ります)。「地図」で山頂の地図を開けます。グリッドは「現在地」でも入ります。
  • 書式が正しくないときは、画面を閉じずに、欄の下に知らせます。
  • メモは # で始まる行として書くので、出力のファイルには入りません(HAMLOG の欄には、設定で書けます)。JCC・JCG などを書きます。山・公園を候補から選ぶか、「現在地」で現在地を取ると、電波があれば JCC・JCG を調べて入れます(国土地理院のデータと、このアプリのサーバーで調べます)。手で書いたメモは、書き換えません。
  • メモの欄が空のまま書き込むと、山(なければ最初の公園)から調べて書きます。調べられなければ書きません。
  • 開いたときのメモの欄は、その位置で有効なメモです。変えて書き込むと、新しい # の行を足します(前のメモは消しません)。同じなら書きません。
  • 「新しいログ」では、バンド(または周波数)とモードも入れられます。指令の行のあと、最初の QSO の前に書きます。
  • 場所を書き込むと、自局のコールサインを覚え、次の「新しいログ」の初期値にします。

PC とスマホの同期

設定(設定の表で「する」のもの)と予定を、端末の間で同期します。ログの本文は同期しません。

  1. PC など、最初の端末: 歯車 →「設定・予定の同期」→「同期を始める(コードを作る)」。QR コードと、26 文字の同期コードが出ます。
  2. スマホ:
    • Android: カメラ(Google レンズなど)で QR を読む → 開いた画面で「参加する」。
    • iPhone: ホーム画面のアプリを開き、歯車 →「QRを読む」で QR を読むか、同期コードを入れて「参加」(カメラで読むと Safari で開くので、ホーム画面のアプリには反映されません)。
  • 参加すると、その端末の設定は、同期している設定で置き換わります。その端末の予定はそのまま残り、同期している予定と合わさります。ログの本文は変わりません。
  • 一度参加すれば、あとは開いたとき(電波のあるところ)に自動で同期します。山頂では電波がなくても、同期済みの予定がそのまま使えます。
  • やめたいときは「同期をやめる」(サーバーの設定・予定も消せます)。

同期コードを知っている人は、設定と予定を読み書きできます。QR やコードは、人に見せないでください。

山頂の地図

メニュー →「山頂の地図」(カーソルの位置で有効な山頂)か、予定・場所の画面の「地図」で開きます。

  • 山頂のアクティベーションゾーン、市区町村の境、市区町村ごとに該当する POTA の公園を出します。
  • 現在地(GPS)を重ね、アクティベーションゾーンの中にいるか、いまいる市区町村はどこか(ログに書く JCC・JCG)、そこで該当する POTA の公園の中にいるかを出します。境界の近く(GPS の誤差と、区域のデータのずれの範囲)では、言い切らずに「境界付近」と出します。
  • 「一部」と書いた公園は、その市区町村の中のゾーンの一部だけが公園です(斜線の区域)。
  • 予定に入れた山頂と、場所を書き込んだ山頂の地図は、電波のあるうちに端末に保存され、電波がなくても見られます。

書き出すファイル

zip の名前は、最初の QSO の日付・運用場所・書き出した時刻です(fle-20261019@JA-ST-012-JP-1151-1543.zip など。書き出すたびに別の名前になり、上書きされません)。「FLEログを保存」も同じ名前で .txt です。

sotaYYYYMMDD.csvSOTA のログ(山の QSO。UTC の日付ごと)。S2S があれば sota-s2s-…csv も
コールサイン@公園-日付.adiPOTA の ADIF(公園ごと。日をまたいでも 1 つで、日付は最初の QSO の日)。WWFF・SOTA(山ごと。名前の / は -)も同じ形。周波数を書いたときは FREQ、山があれば MY_SOTA_REF(自分)・SOTA_REF(相手)も入ります

contest-日付.txtコンテストのログのときに作られる、ZLOG 形式のファイル
  • SOTA・POTA・WWFF のファイルは、いつも UTC です。
  • 誤りのある行があるときは、これらのファイルは作られず、誤りを書いたテキストだけが出ます。
  • 日付・自局・運用場所が足りないとき、聞き取れなかった文字 ? のあるコールサインがあるときは、書き出しの前に確認の画面が出ます。

FLE の書き方

ログは行単位です。空行は無視されます。# から行末まではメモで、出力には入りません。

指令の行(現れた行から先が有効)

mycall JL1NIE/1自局のコールサイン
operator JL1NIE運用者(省略すると自局から)
mysota JA/KN-028自局の山。- で解除
mypota JP-0001 JP-0002自局の公園(重なる公園は並べる)。- で解除
mywwff JAFF-0001自局の WWFF
mygrid PM95uq自局のグリッド(4・6・8 文字)
date 2026-10-25日付(10/25 も可)。時刻は 00:00 に戻る
day + / day ++日付を 1 / 2 日進める(0 時をまたぐとき)。自動で入るときの動きは「0 時をまたぐとき」を見てください
timezone jst時刻の時間帯。jst、utc、+9 のような数字。省略すると UTC。ふつうは設定の「タイムゾーン」が先頭に書きます。ログの途中で変えると、直前の時刻を同じ瞬間のまま新しい時間帯で読み替えます(UTC 23:30 のあとの timezone jst は、翌日の 08:30 から続きます)
rig KX2+EFHWリグ(HAMLOG の Rig=)。- で解除
qslmsg …QSL メッセージ。$mysota $mypota $mywwff $rig が使える

QSO の行

次の語を、順番を気にせず並べます。

時刻1〜4 桁の数字。1 桁=分の 1 の位、2 桁=分、3 桁=H:MM、4 桁=HH:MM。省いた上の桁は前の行から引き継ぐ
バンド40m 2m 70cm など。次のバンドまで続く
周波数7.030(MHz)。バンドも決まる
モードcw ssb fm am ft8 など。次のモードまで続く
コールサイン1 行に 1 つ。ここで QSO が 1 件できる。聞き取れなかった文字は ?(JA1AB?)
レポートコールサインのあとの数字。1 つなら送ったレポート、2 つなら送ったレポートと、もらったレポート。
省いた桁は、モードに合わせて補います(□ は打った数字)。
CW など: 1 桁=5□9(7→579)、2 桁=□□9(44→449)
SSB・FM・AM: 1 桁=5□(7→57)、2 桁=そのまま
3 桁は、どのモードでもそのまま。FT8 などは -18 のような SNR
相手の山・公園ja/st-012 か st-012(SOTA。アソシエーションを省けるのは、自分の山があるときだけ)、jp-1234(POTA)、jaff-0001(WWFF)
相手のグリッドpm85rl。コールサインの後ろに書く。HAMLOG の GL と、ADIF の GRIDSQUARE に入る
メッセージ<…> QSO メッセージ、[…] QSL メッセージ、{…} 備考
