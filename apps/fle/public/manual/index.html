FLEonline 使い方

English · ← アプリに戻る

山や公園で、スマホから運用ログを書き、SOTA / POTA / HAMLOG 用のファイルにするアプリです。ここでは、ふつうの SOTA アクティベーションを例に、準備から ADIF などの生成までを順に説明します。最後に、ログの書き方(FLE)の一覧があります。

  1. 最初に: ホーム画面に追加
  2. 出発前(PC): 設定と予定を登録する
  3. PC とスマホを同期する
  4. 山頂で: ログを書く
  5. 運用後: ファイルを作る
  6. FLE の書き方(リファレンス)

1. 最初に: ホーム画面に追加

電波のない山頂でも使えるよう、事前に一度、電波のあるところで開いて、ホーム画面に追加してください。

  • iPhone: Safari で開き、共有ボタン →「ホーム画面に追加」。
  • Android: Chrome のメニュー →「ホーム画面に追加」(またはアプリのメニューの「ホーム画面に追加」)。

一度開いたあとは、オフラインでも書けます。書いたログは、端末に自動で保存されます。山・公園の候補検索と、同期だけは、電波が要ります。

2. 出発前(PC): 設定と予定を登録する

PC のブラウザで https://fleonline.sotalive.net/ を開きます。

設定

画面右上の歯車が設定です。

  • リグの一覧: 使うリグ・アンテナを 1 行に 1 つ書いておくと、ログで rig と打ったときに候補に出ます(例: KX2+EFHW)。HAMLOG を使う人は、HAMLOG に登録している名前を書きます。
  • 時間帯: 時刻をどの時間帯で書くか(UTC / JST など)。SOTA・POTA の ADIF は、いつも UTC で出ます。HAMLOG のファイルだけは、ここで選んだ時間帯で出ます。
  • 時刻を自動で入れる: 時刻のない QSO の行を確定すると、いまの時刻を入れます(既定はオン)。紙ログを後から打ち込むときはオフにします。時刻のない行は、前の行の時刻を引き継ぎます。端末ごとの設定で、同期しません。
  • 確定の書き方: 緑のバーで確定するとき、バンド・モードや RST も書くかどうか。

予定(行き先)

メニュー(「…」)→「予定」→「予定を追加」で、行く山をあらかじめ登録します。

名前例: 高尾山 10/25(自分用の名前)
日付任意。運用の日
自局コールサイン(例: JL1NIE/1)
SOTA / POTA / WWFF名前や番号を打つと候補が出ます(高尾、TK-0 など)。山・公園を選ぶだけです
グリッド任意。「現在地」ボタンでも入ります
リグ・QSLメッセージ任意。リグは HAMLOG の Rig= に入ります。QSLメッセージには $mysota や $rig が使えます

予定は何件でも(50 件まで)登録できます。当日はここから選ぶだけです。

3. PC とスマホを同期する

設定と予定は、PC で入れたものを、スマホでも使えるよう同期できます。ログの本文は同期しません(スマホで書いたログは、スマホの中だけにあります)。

PC 側

  1. 歯車 →「設定・予定の同期」→「同期を始める(コードを作る)」。
  2. QR コードと、26 文字の同期コードが出ます。

スマホ側

  • Android: カメラ(Google レンズなど)で QR を読む → 開いた画面で「参加する」。
  • iPhone: Safari と、ホーム画面に追加したアプリは、保存領域が別です。ホーム画面のアプリを開き、歯車 →「QRを読む」で PC の QR を読むか、同期コードを入力して「参加」。

一度参加すれば、あとは自動で同期します。PC で予定を足すと、スマホを開いたとき(電波のあるところ)に入ります。山頂では電波がなくても、同期済みの予定がそのまま使えます。

同期コードを知っている人は、設定と予定を読み書きできます。QR やコードは、人に見せないでください。やめたいときは、設定の「同期をやめる」(サーバーの内容も消せます)。

4. 山頂で: ログを書く

はじめに: 予定を選ぶ

  1. メニュー →「新しいログ」。
  2. 「予定から選ぶ」で今日の予定を押すと、自局・山・グリッドなどが入ります。
  3. 「ログに書き込む」を押すと、ログの先頭に次のような行が入ります。
mycall JL1NIE/1
mysota JA/TK-001
date 2026-10-25
rig KX2+EFHW
qslmsg $mysota $rig

予定を使わずに、その場で自局や山を入れてもかまいません(山の名前から候補が出ます)。

QSO を書く

入力欄に、1 行に 1 QSO ずつ書きます。最初に、バンドとモードを 1 行で書きます。

40m cw
0230 ja1abc
35 ja2xyz 579
41 jr1qrp/1 ja/st-012
ssb
52 ja3pqr
20m ssb
58 ja8abc
  • 0230 ja1abc: 02:30 に JA1ABC。時刻は、前の行から引き継ぐので、次からは分だけ(35 → 02:35)で書けます。
  • バンド・モードは、書き換えるまで続きます。モードだけ変えるなら ssb、バンドも変えるなら 20m ssb を 1 行書きます。
  • 579: 送ったレポート。省略すると、モードの標準(CW 599 / SSB 59)になります。5 7 のように、受け取ったレポートも書けます。
  • ja/st-012: 相手が山にいる(S2S)。相手の公園(jp-1234)も、同じように書きます。
  • pm85rl: 相手のグリッド。コールサインの後ろに書きます。HAMLOG の GL と、ADIF の GRIDSQUARE に入ります。
  • <山田さん> や {QRP} で、メッセージ・備考を添えられます。

画面の見かた

入力欄の下の「候補バー」が、いま書いている行の解釈を見せます。

橙入力の途中です。コールサインなどが、まだ確定できる形ではありません。手を止めると、足りないものが出ます。
緑解釈できました。バンド・モード・時刻・レポートが補われた姿が出ます。右端の ✓ を押すと確定して、次の行へ進みます。コール・RST・時刻を押すと、ログ欄のその末尾へキャレットが移ります。⌫ で末尾から直せます(RST は押すたびに受信 → 送信。書いていない RST や時刻は、書き込んでから移ります)。途中の文字は、数字の行をなぞって合わせます(QSO を直す)。
赤バンドやモードの書き忘れなど、直す必要があります。
(空の行)いまの時刻と、その行の時点のバンド・モードが出ます。次の QSO には、この値が入ります。
(指令の行)行からは見えない値が出ます。day + なら進んだ先の日付(曜日つき)、mysota などなら山・公園の名前(オンラインのとき)、qslmsg なら変数を置き換えた文面、rig ならリグ(rig - なら「リグなし」)。補うものがない行(mycall やコメントの行など)は、空の行と同じです。

左の数は、カーソルの日(UTC)の QSO の数で、その下に全体の数(/10 など)が出ます。設定の「QSO の数」で、全体の数だけにもできます。押すと、QSO の一覧と誤りが見られます。誤りをタップすると、その行へ移ります。

  • 入力欄の上に出る補完候補を押すと、キーワード・バンド・モードが入ります。
  • 設定で「数字キー」をオンにすると、キーボードの上に数字の行が出ます(コールサインの数字が打ちやすくなります)。数字の行を左右になぞると、カーソルが 1 文字ずつ動きます(行の中の位置を細かく合わせるとき。だいたいの位置へは、ログ欄をタップ)。
  • 場所を移動したときは、メニュー →「新しいログ」で、そこから先のQSOの場所を切り替えられます。

QSO を直す

交信中にレポートやコールサインを言い直されたときは、緑の候補バーの、直したい要素を押します。ログ欄のキャレットが、その要素の末尾へ移るので、⌫ で末尾から消して打ち直します(選択はしないので、打っても他の文字は消えません)。

押すところキャレットの移り先(|)
コール1005 ja1xyz| 57 599
RST(1 回目)1005 ja1xyz 57 599| もらったレポート(言い直してくるのは、たいていこちら)
RST(続けてもう 1 回)1005 ja1xyz 57| 599 送ったレポート
時刻1005| ja1xyz 57 599
  • 例: もらったレポートが 599 ではなく 579 だった → RST を押す → ⌫ ⌫ → 79。
  • 例: JA1XYZ ではなく JA1XYW だった → コールを押す → ⌫ → w。
  • 省いて書いた RST や時刻(バーには補った値が出ています)を押すと、その値を行に書き込んでから、末尾へ移ります。たとえば ja1xyz の行で RST を押すと ja1xyz 599 599| になります。
  • 途中の文字を直すときは、要素を押して末尾へ移ってから、数字の行を左右になぞってキャレットを合わせます(次の節)。
  • 前の QSO を直すときは、ログ欄でその行をタップします。その行が緑のバーに出るので、同じように直せます。誤りのある行は、左の QSO の数を押すと一覧が出て、タップでその行へ移れます。
  • 確定(次の行へ進む)は、緑のバーの右端の ✓ だけです。要素を押しても確定はしません。

数字の行をなぞって、キャレットを動かす

指で文字と文字の間を狙わなくても、キャレットを 1 文字ずつ動かせます。QSO 以外の行(date、mysota、qslmsg、コメントなど)は、緑のバーで要素を選べないので、これが直し方の中心になります。QSO の行でも、要素の途中を直すときに使います。

[1][2][3][4][5][6][7][8][9][0][/][-]
  ← 指を置いたまま滑らせる →
  1. 数字の行のどこかに指を置きます(どのキーからでもかまいません)。
  2. 指を離さずに、左右へ滑らせます。約 20px ごとに 1 文字、滑らせた向きへキャレットが動きます。行や要素を越えても動きます。
  3. 指を離すと止まります。なぞったときは、数字は入りません。
  • ほとんど動かさずに(10px 未満)離したときは、ふつうのタップとして、その数字が入ります。
  • 例: mypota jp-1151 jp-1164 の 1151 を 1152 にする → ログ欄の 1151 のあたりをタップ → 数字の行をなぞって 1151| に合わせる → ⌫ → 2。
  • 例: date 2026-10-19 を 18 日にする → 行の末尾をタップ(19|) → ⌫ → 8。末尾ならなぞる必要はありません。
  • 例: 送ったレポート 559 の真ん中の 5 を 7 にする → RST を 2 回押して 559| → 数字の行を左へ 1 文字分なぞって 55|9 → ⌫ → 7 で 579。
  • だいたいの位置へはログ欄をタップし、細かい位置合わせをなぞりで行うと楽です。
  • 数字の行は、設定の「数字キーの行」で出します(タッチの端末では、最初から出ています)。

5. 運用後: ファイルを作る

  1. メニュー(「…」)→「書き出し (ADIF等)」を押します。
  2. 足りない情報(自局・日付・運用場所・グリッドなど)があると、確認の画面が出ます。「ログに書き込んで生成」か「このまま生成」を選びます。
  3. zip ファイルがダウンロードされます。名前は、最初の QSO の日付・運用場所・書き出した時刻です(fle-20261019@JA-ST-012-JP-1151-1543.zip など。書き出すたびに別の名前になり、上書きされません)。「FLEログを保存」も同じ名前で .txt です。
sotaYYYYMMDD.csvSOTA のログ(山のQSO。日付ごと)。S2S があれば sota-s2s-…csv も
コールサイン@公園-日付.adiPOTA の ADIF(公園・日付ごと)。WWFF も同様
hamlog-….csvHAMLOG の取り込み用 CSV(QSLメッセージ・リグ入り)

SOTA のデータベースには sota…csv を、POTA のサイトには .adi を、HAMLOG には hamlog…csv を取り込みます。エラーのある行があるときは、ファイルは作られず、エラー内容を書いたテキストだけが出ます(直してから、もう一度生成します)。

ほかのログソフトのファイルを変換したいときは、logconv2 を使ってください。

FLE のログそのものを残したいときは、メニュー →「FLEログを保存」でテキストファイルに保存できます。「FLEログを開く」で、また読み込めます。

6. FLE の書き方(リファレンス)

ログは行単位です。空行は無視され、# から行末までは注釈です。

指令の行(現れた行から先が有効)

mycall JL1NIE/1自局のコールサイン
operator JL1NIE運用者(省略すると自局から)
mysota JA/TK-001自局の山。- で解除
mypota JP-0001 JP-0002自局の公園(重なる公園は並べる)。- で解除
mywwff JAFF-0001自局の WWFF
mygrid PM95uq自局のグリッド(4・6・8 文字)
date 2026-10-25日付(10/25 も可)。時刻は 00:00 に戻る
day + / day ++日付を 1 / 2 日進める(UTC の日付をまたぐとき)
timezone jst以降の時刻の時間帯。jst、utc、+9 のような数字。省略は UTC
rig KX2+EFHWリグ(HAMLOG の Rig=)。- で解除
qslmsg …QSLメッセージ。$mysota $mypota $mywwff $rig が使える

QSO の行

次の語を、順番を気にせず並べます。

時刻1〜4 桁の数字。1 桁=分の 1 の位、2 桁=分、3 桁=H:MM、4 桁=HH:MM。前の行から引き継ぐ
バンド40m 2m 70cm など。次のバンドまで続く
周波数7.030(MHz)。バンドも決まる
モードcw ssb fm am ft8 など。次のモードまで続く
コールサイン1 行に 1 つ。ここで QSO が 1 件できる
レポートコールサインのあとの数字。1 つ=送信、2 つ=送信と受信。1 桁=5□9、2 桁=RS、3 桁=RST。FT8 などは -18 のような SNR
相手の山・公園ja/st-012(SOTA)、jp-1234(POTA)、jaff-0001(WWFF)
メッセージ<…> QSOメッセージ、[…] QSLメッセージ、{…} 備考

よくある誤り

  • 「バンドがない / モードがない」: コールサインの前に 40m cw の行を書いてください。
  • 「rigset は rig になりました」: 古い rigset の行を、rig KX2+EFHW のように書き直してください。
  • コールサインの形が違う: 数字で始まるもの(7K1ABC など)を含め、国際形式で書いてください。

文法の詳しい仕様は、docs/fle-grammar.md にあります。元になった FLE(Fast Log Entry)の考え方は、こちらの記事にあります。
