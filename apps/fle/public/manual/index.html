1. このアプリについて

山や公園での運用ログを、スマホ 1 台で、その場で書くアプリです。書き方は FLE(Fast Log Entry)で、前の行と同じところは省きます(40m cw → 0230 ja1abc → 35 ja2xyz)。電波のない山頂でも書けます。帰ってから、SOTA・POTA・WWFF・HAMLOG のファイルを一度に作ります。

できること

書く1 行に 1 QSO を書きます。省いた時刻・バンド・モード・RST を補った結果が、ログ欄の下の候補バーに出ます。スマホでは、画面上のキーボード(フルキー)で打ちます *1)
電波がなくても一度開いておけば、電波がなくても書けます。ログは端末に自動で保存します
準備する行き先を「予定」に登録し、当日は選ぶだけにします。山頂の地図で、アクティベーションゾーン・市区町村(JCC・JCG)・POTA の公園を確かめます
PC と同期する設定と予定を、PC とスマホで同期します
ファイルを作るSOTA の CSV、POTA・WWFF・SOTA の ADIF、HAMLOG の CSV を、zip で一度に作ります。ほかのログソフトの ADIF も、ログに足せます

*1) FLE を打つのに必要なキーだけを並べたキーボードです(「スマホのキーボード」)。

できないこと・注意

  • ログの本文は同期しません。スマホで書いたログは、スマホの中だけにあります。
  • SOTA・POTA などのサイトへは送信しません。作ったファイルを、各サイトに自分で取り込んでください。
  • 山・公園の候補の検索、JCC・JCG の照会、同期には、電波が要ります。

Note: アクティベーション(自分が山・公園から運用する)のためのアプリです。自宅からのチェイスでは、SOTA・POTA・WWFF の場所ごとのファイルは作りません(全 QSO の ADIF、HAMLOG の CSV、チェイス用の SOTA の CSV は作ります)。

2. 初期設定(最初に一度だけ)

ホーム画面に追加する(任意)

  1. iPhone: Safari で開き、共有ボタン →「ホーム画面に追加」を押します。
  2. Android: Chrome のメニュー(またはこのアプリのメニュー)→「ホーム画面に追加」を押します。
  3. 電波のあるところで、一度アプリを開いておきます *1)。

Note: ブラウザーのままでも使えます。iPhone では、Safari とホーム画面のアプリとで、データが別々に保存されます。どちらか一方で使い続けてください。

*1) 追加してもしなくても、電波のない山頂で使う前に必要です。

最初に決める設定

画面右上の歯車で設定を開き、次の 3 つを確かめます。ほかは最初の値のままで使えます(すべての設定は「設定」)。

タイムゾーンログの時刻を書く時間帯を選びます。最初は UTC。日本時間で書くなら JST にします *1)
よく使うリグ1 行に 1 つ書きます(例: KX2+EFHW)。ログで rig と打つと候補に出ます *2)
HAMLOG の時刻・出力HAMLOG を使うときだけ。CSV の時刻(JST J / UTC U)と、QTH・Rmks1・Rmks2 に書く項目を選びます

*1) UTC 以外にすると、ログの先頭に timezone の行が入ります。
*2) HAMLOG を使うなら、HAMLOG で定義した名前を書きます。

PC も使うなら

予定の登録は PC で行い、同期でスマホに写します。

Note: スマホだけでも、すべての操作ができます。

3. 前日: 準備する

ふつうの SOTA アクティベーションを例にします。POTA・WWFF で違うところは Note に書きます。

予定を登録する

  1. メニュー(「…」)→「予定」→「予定を追加」を押します。
  2. 次の項目を入れます。
  3. 「保存」を押します。
名前自分用の名前(例: 陣馬山 10/25)
日付任意。運用の日
自局コールサイン(例: JL1NIE/1)
SOTA / POTA / WWFF名前や番号を打ち(陣馬、KN-02 など)、候補から選びます
グリッド任意。「現在地」ボタンでも入ります
リグ・QSL メッセージ任意 *1)
備考#任意。JCC・JCG など *2)

Note: POTA で公園が重なるところでは、POTA の欄に公園を並べます(JP-1151 JP-1164)。

*1) リグは HAMLOG の Rig= に入ります。QSL メッセージには $mysota や $rig を使えます。
*2) 山・公園を選ぶと、電波があれば調べて入ります。

山頂の地図で確かめる

  1. 予定の SOTA 欄の横の「地図」を押します。
  2. アクティベーションゾーン、市区町村の境、市区町村ごとの POTA の公園を確かめます。
  3. 都県境の山では、どちら側で運用するか(備考#に書く JCC・JCG と、POTA の公園)を決めます。

詳しくは「山頂の地図」。

出発前に確かめる

  • 地図の保存: 予定の一覧に「地図: 保存済み」と出ているか確かめます。「まだ保存していません」なら、電波のあるところでアプリを開きます *1)。
  • PC で予定を入れたとき: 電波のあるところでスマホのアプリを開き、予定が入ったか確かめます *2)。
  • ホーム画面に追加したときは、ホーム画面から開けるか確かめます。

*1) 予定に入れた山頂の地図は、電波のあるところでアプリを開いたときに、自動で保存します。保存済みなら、山頂で電波がなくても見られます。
*2) 同期は、アプリを開いたときに行います。

4. 当日: ログを書く

新しいログを始める

  1. メニュー →「新しいログ」を押します *1)。
  2. 「予定から選ぶ」で今日の予定を押します *2)。
  3. 必要なら、バンド(または周波数)とモードを入れます。
  4. 「ログに書き込む」を押します *3)。
mycall JL1NIE/1
mysota JA/KN-028
date 2026-10-25
rig KX2+EFHW
qslmsg $mysota $rig
# JCC#111001 相模原市緑区
40m cw

Note: 予定を使わずに、その場で自局や山を入れてもかまいません。# で始まる行は備考#(JCC・JCG など)で、出力のファイルには入りません。

*1) 自局のコールサインは、前に入れたものが入っています。
*2) 自局・山・グリッド・備考#などが入ります。
*3) いま書いていたログが、上のような行で始まる新しいログに置き換わります。置き換える前のログは、メニューの「元に戻す」で戻せます。

アクティベーションゾーンの中か確かめる

  1. QSO を始める前に、メニュー →「山頂の地図」を開きます。
  2. 地図の下に、山頂のコードが緑で出ているか確かめます *1)。
  3. 一覧の ▶ の付いた市区町村(いまいるところ)を確かめます *2)。

*1) 現在地(GPS)がゾーンの中なら緑で出ます。公園の中なら、その公園のコードも出ます。
*2) 備考#に書く JCC・JCG です。陣馬山のような都県境の山では、どちら側にいるかもここで確かめます。

QSO を書く

1 行に 1 QSO ずつ書きます。

40m cw
0230 ja1abc
35 ja2xyz 579
41 jr1qrp/1 st-012
ssb
52 ja3pqr
0230 ja1abc02:30 に JA1ABC。次の行からは分だけ書きます(35 → 02:35)*1)
579送ったレポート。省くとモードの標準(CW 599 / SSB 59)
st-012相手の山(S2S)*2)。相手の公園(jp-1234、P2P)も同じように書きます
ssbバンド・モードは、書き換えるまで続きます(ssb、20m ssb)

Note: 時刻は自動で入ります(設定「時刻を自動で入れる」。最初はオン)。時刻を書かずにコールサインを打って OK を押すと、その行の最初の 1 文字を打った時刻が入ります。

*1) 時の桁は前の行から引き継ぎます。
*2) 自分の山と同じアソシエーション(ja/)は省けます。

書き方のすべては「FLE の書き方」。

確定して次の行へ(OK)

  1. 候補バーが緑になったか確かめます *1)。
  2. 右端の ✓ OK を押します *2)。
  • 候補バーが橙なら入力の途中、赤なら直してください(「画面の見かた」)。
  • キーボードの ↵ は改行だけで、時刻は書きません。

Note: QSO は、OK を押さなくても、正しく書けた時点でログに入っています。ただし、時刻を書いていない行は前の行の時刻になります。いまの時刻を入れるには OK を押します。

*1) 緑は、その行を QSO として読めた印です。
*2) 時刻などを書き足して、次の行へ進みます。

その場で直す

  1. 候補バーの、直したい要素(コール・RST・時刻)を押します *1)。
  2. ⌫ で消して打ち直します。
  • RST は、1 回押すともらったレポート、もう 1 回押すと送ったレポートへ移ります。
  • 消しすぎたときは、キーボードの ↶ で戻します。

*1) ログ欄のカーソルが、その要素の末尾へ移ります。詳しくは「QSO を直す」。

QSO の数を見る

候補バーの左の数で、その日の QSO の数を見ます *1)。

*1) 下の小さい数は、アクティベーションの成立に必要な QSO の数(SOTA /4、POTA /10)です。届くと緑になります。

場所を移るとき

  1. 新しい場所で最初の QSO を書く行に、カーソルを置きます。
  2. メニュー →「場所の変更」を開き、新しい山・公園を書き込みます *1)。

*1) その行から先の QSO の場所が変わります。ログは同じままです。

0 時をまたぐとき

  • 時刻を自動で入れているとき: OK を押すと day + の行が自動で入り、画面の下に通知が出ます。
  • 時刻を手で打っているとき: 前の QSO が 21 時以降で、この行が 3 時より前(2358 のあとの 0002 など)なら、OK で day + が入ります。ログの上に「newday です」と約 3 秒出ます。

Note: どちらも、出ている間に「元に戻す」を押すと取り消せます。

ほかのアクティベーション局を呼びまわるとき

相手の山・公園も書きます(ja1abc tk-001)。その行には、打ち始めた時刻ではなく、OK を押した時刻が入ります *1)。

Note: CQ を出していて S2S の局に呼ばれた行も、OK を押した時刻になります(交信が短いので、ずれは小さい)。設定「チェイス・S2S・P2P の行は、OK を押した時刻にする」(最初はオン)で変えられます。

*1) 相手を聞いて書き始めてから、順番を待って呼ぶため、打ち始めの時刻だと実際の交信と大きくずれることがあります。

5. 終わってから: ファイルを作る

  1. メニュー →「書き出し (ADIF等)」を押します。
  2. 確認の画面が出たら、次のどちらかを選びます *1)。
    • 日付・自局が足りないとき: 「ログに書き込んで出力」か「このまま出力」。
    • SOTA/POTA/WWFF がないとき(「注意」): 「SOTA・POTA・WWFF を設定する」→ 場所の画面で「ログに書き込んで出力」。設定しないなら「SOTA・POTA・WWFF のファイルなしで出力」*2)。
  3. ダウンロードした zip の中のファイルを、それぞれのサイト・ソフトに取り込みます。
sotaYYYYMMDD.csvSOTA のデータベースに取り込む
コールサイン@公園-日付.adiPOTA のサイトに取り込む(公園ごと)
コールサイン@山-日付.adiSOTA のサイトに ADIF で取り込む(山ごと)*3)。WWFF の ADIF も同じ形
adif-….adi全 QSO の ADIF。LoTW・QRZ.com・ほかのログソフトに取り込む
hamlog-….csvHAMLOG に取り込む
fle-….txt元の FLE ログ(「FLEログを保存」と同じ)。手元に残す

Note: 誤りのある行があるときは、ファイルは作られず、誤りを書いたテキストと元の FLE ログだけが入ります。直してから、もう一度書き出してください。ファイルの中身は「書き出すファイル」。

*1) 日付・自局・SOTA/POTA/WWFF が足りないときだけ出ます。グリッドは任意なので、なくても出ません。
*2) zip には、全 QSO の ADIF、HAMLOG の CSV、チェイス用の SOTA の CSV、元の FLE ログが入ります。場所の画面でキャンセルすると、確認の画面に戻ります。
*3) 山の名前の / は - になります。SOTA は CSV でも取り込めます。

書いている途中で止まったとき

ログは、打つたびに端末の中へ自動で保存します *1)。保存の操作は要りません。

  • ブラウザーを開き直すと、前のログがそのまま出ます(履歴から開き直したとき、閉じたタブも、同じブラウザーなら残っています)。
  • 山頂でも、区切りのよいところで、メニュー →「FLEログを保存」でファイルにしておきます。

Note: 端末が固まった・電池が切れたときは、保存が済んだところまでが残ります。直前の約 0.4 秒に打った文字は失われることがあります。端末が突然止まり、ブラウザーが書き込みを終える前だと、それより前の数行も失われることがあります。
ブラウザーの「閲覧データを削除」「サイトデータの消去」をすると、ログも消えます。iPhone では、Safari とホーム画面のアプリとで保存領域が別です(「初期設定」)。

*1) 最後に打ってから約 0.4 秒後と、アプリを閉じる・ほかのアプリに切り替えるときに、ブラウザーの保存領域へ書きます。

FLE ログを保存する

メニュー →「FLEログを保存」で、ログをテキストファイルにします。あとで「FLEログを開く」で読み込みます。

Note: 書き出しの zip にも、同じものが入っています。

ほかのログソフトの ADIF を足す

メニュー →「ADIFを追加」で、別のログソフトの ADIF を FLE の行にして、ログの末尾に足します。

Note: 足す前のログは「元に戻す」で戻せます。

時間帯を間違えたとき

  1. 設定のタイムゾーンを、正しい時間帯に変えます。
  2. QSO のあるログでは、次のどちらかを選びます。
    • 変換する: 同じ瞬間の、新しい時間帯の時刻に書き直す。
    • 時刻はそのまま: timezone の行だけを書き換える *1)。

*1) JST で書いたのに timezone を書き忘れた(設定が UTC だった)ときは、こちらを選びます。

6. 画面・設定・書き方の説明

画面の見かた

ログ欄の下の候補バーに、カーソルのある行の解釈が出ます。色で状態がわかります。

橙入力の途中です。コールサインなどが、まだ確定できる形ではありません。手を止めると、足りないものが出ます。
緑解釈できました。時刻・バンド・モード・レポートを補った結果が出ます。右端の ✓ OK で、時刻などを書き足して次の行へ進みます *1)。コール・RST・時刻を押すと、ログ欄のその要素の末尾へカーソルが移ります(「QSO を直す」)。
赤バンドやモードの書き忘れなど、直す必要があります。
(空の行)いまの時刻と、その行の時点のバンド・モードが出ます。次の QSO には、この値が入ります。
(指令の行)行からは見えない値が出ます。day + なら進んだ先の日付(曜日つき)、mysota などなら山・公園の名前(電波があるとき)、qslmsg なら変数を置き換えた文面、rig ならリグ(rig - なら「リグなし」)。
  • QSO の数: 候補バーの左に、カーソルのある日(UTC の日付)の QSO の数を大きく、全体の数を小さく出します。SOTA・POTA の運用では、小さい数はアクティベーションの成立に必要な QSO の数(SOTA /4、POTA /10)になり、その数に届くと緑になります。誤りのある行があると赤になり、⚠2 のように誤りの数も出ます。設定の「QSO の数」で、全体の数だけにもできます。
  • 時刻と運用先: ログ欄の上に、時刻と、自局のコールサイン、カーソルの行で有効な山・WWFF・公園を大きく出します。その下には、カーソルの行で有効な備考#(それより前で最後の # の行)を出します。時刻は、ログに入る時刻と同じタイムゾーンで出し、UTC でなければ UTC も添えます。画面が狭くて入らないとき(OS のキーボードを出したときなど)は出ません。
  • 補完候補: 打っている途中で、キーワード・バンド・モードなどの候補が候補バーに重ねて出ます。押すと入ります。
  • ログは下に寄せて表示し、打っている行が候補バーのすぐ上に来ます。
  • スマホを横向きにすると「縦向きにしてお使いください」と出ます(ログはそのまま)。

*1) 最後の行なら新しい行を足します。ログの途中なら次の行へ移るだけです(行は増えません)。

スマホのキーボード(フルキー)

スマホなど、タッチ操作の端末では、OS のキーボードの代わりに、FLE を打つのに必要なキーだけを並べた画面上のキーボード(フルキー)が出ます *1)。

      10:05:12 JST  UTC 01:05
       JA1ABC  JA/KN-028
│ 1111 jj0pic         │
│ 2107 ja1xyz 7▌      │ (打っている行)
[3/10][JA1XYZ 579/599   ][✓]
[1][2][3][4][5][6][7][8][9][0]
[Q][W][E][R][T][Y][U][I][O][P]
[A][S][D][F][G][H][J][K][L][-]
[↑][Z][X][C][V][B][N][M][/][⌫]
[🌐][↶][←][            ][→][ ↵ ]
  • ログ欄をタップしても、OS のキーボードは出ません(カーソルは出ます)。
  • 英字はログに小文字で入ります(FLE は大文字・小文字を区別しません)。- は L の右、/ は M の右です。
  • 続けて 2 回押すと、別の文字になります。/ を 2 回で .(7.0295 のような周波数に)、- を 2 回で ,。キーの右下に小さく出ています。
  • 長押し(0.5 秒ほど)で、別の記号が入ります。3 は #(備考#の行や JCC# に)、0 は +(day + に)、7 は ?(聞き取れなかった文字に。JA1AB? のように打っておくと、書き出しの前に知らせます)。押している間の吹き出しが記号に変わり、離すと入ります。
  • Z の左は Caps(↑)です。押すと ↑ が塗りつぶしになり、英字が大文字で入ります *2)。この状態は端末ごとに覚えます。
  • 下の段のいちばん広いキーが空白、右下が ↵ です(文字は書いていません)。
  • ↵ は改行するだけで、確定はしません(時刻などは書きません)。行の途中なら、そこで行が割れます。ログの途中で押せば、間に QSO を足せます。確定は候補バーの ✓ OK です。
  • ↶ は、直前の編集を取り消します(「取り消しと「元に戻す」」)。
  • ⌫ は、押し続けると続けて消します。
  • 空白キーか ← → キーの上で左右になぞると、カーソルが 1 文字ずつ動きます(「なぞってカーソルを動かす」)。
  • キーの高さは、キーボードの上の縁のつまみを上下にドラッグして変えます(キーが正方形になる高さから、その 1.5 倍まで)*3)。端末ごとに覚えます。
  • 日本語(<山田さん> のようなメッセージや、qslmsg)は、🌐 で OS のキーボードに切り替えて打ちます。終わったら、下に出る「フルキーに戻る」を押します。
  • 「新しいログ」「場所の変更」「予定」などの画面でも、自局・SOTA・POTA・WWFF・グリッド・備考#の欄は、同じキーボードで打ちます(英字は最初から大文字)。↵ で次の欄へ進みます。備考#に日本語(市区町村名など)を書くときは、🌐 で OS のキーボードに切り替えます。予定の名前は、はじめから OS のキーボードです。

*1) かな入力から英数字へ切り替える手間がありません。
*2) 小文字の m と n を見分けにくいときに使います。
*3) 手袋をしているときなどに使います。

PC で使うとき

PC では、物理キーボードで打ちます(フルキーは出ません)。スマホとの違いは次のとおりです。

  • Ctrl+Z(Mac は ⌘Z)で、直前の編集を取り消します。フルキーの ↶ と同じ取り消し方です。
  • 補完候補は、ログ欄の下端に重ねて出ます。
  • 候補バーの左の QSO の数をクリックすると、QSO と誤りの一覧が出ます。誤りをクリックすると、その行へ移ります(スマホでは、メニュー →「QSO一覧」)。
  • 設定の「数字キーの行」をオンにすると、ログ欄の下に数字のキーが出ます(コールサインの数字や / - が打ちやすくなります)。左右になぞると、カーソルが動きます。
  • 確定のときに RST を書くかは、PC とスマホで別に設定します(PC は最初から書き、スマホは最初は書きません)。

QSO を直す

  1. 候補バーの、直したい要素を押します。ログ欄のカーソルが、その要素の末尾へ移ります *1)。
  2. ⌫ で末尾から消して、打ち直します。
押すところカーソルの移り先(|)
コール1005 ja1xyz| 57 599
RST(1 回目)1005 ja1xyz 57 599| もらったレポート
RST(続けてもう 1 回)1005 ja1xyz 57| 599 送ったレポート
時刻1005| ja1xyz 57 599
  • 例: もらったレポートが 599 ではなく 579 だった → RST を押す → ⌫ ⌫ → 79(言い直してくるのは、たいていもらったレポートです)。
  • 例: JA1XYZ ではなく JA1XYW だった → コールを押す → ⌫ → w。
  • 省いて書いた RST や時刻(バーには補った値が出ています)を押すと、その値を行に書き込んでから末尾へ移ります。ja1xyz の行で RST を押すと ja1xyz 599 599| になります。
  • 途中の文字は、要素を押して末尾へ移ってから、なぞってカーソルを合わせます。
  • 前の QSO を直すときは、ログ欄でその行をタップします。その行が候補バーに出るので、同じように直せます。
  • 要素を押しても、次の行へは進みません。

*1) 選択はしないので、打っても他の文字は消えません。

なぞってカーソルを動かす

文字と文字の間を指で狙わずに、カーソルを 1 文字ずつ動かします *1)。

  1. スマホでは空白キーか ← → キーに、PC では数字の行に、指を置きます。
  2. 指を離さずに、左右へなぞります。約 20px ごとに 1 文字、なぞった向きへカーソルが動きます。行や要素を越えても動きます。
  3. 指を離すと止まります。なぞったときは、指を置いたキーの文字(空白・数字)は入りません。
  • 1 文字だけなら、← → を押しても動きます。
  • 例: mypota jp-1151 jp-1164 の 1151 を 1152 にする → 1151 のあたりをタップ → なぞって 1151| に合わせる → ⌫ → 2。
  • 例: 送ったレポート 559 の真ん中の 5 を 7 にする → RST を 2 回押して 559| → 左へ 1 文字分なぞって 55|9 → ⌫ → 7。

Note: だいたいの位置へはログ欄をタップし、細かい位置合わせはなぞりで行います。

*1) date・mysota・qslmsg などの QSO でない行は、候補バーで要素を選べないので、これが直し方の中心になります。

取り消しと「元に戻す」

↶ / Ctrl+Z直前の編集を取り消します。⌫ で続けて消した分は、1 回で、消し始める前の状態に戻ります(前の行まで消していても)。続けて打った分は、1 回で 1 行分ずつ戻ります。押すたびに、さらに前へ戻ります。OK や候補で書き換えた分も戻せます
通知の「元に戻す」「すべて消す」「新しいログ」「FLEログを開く」「サンプル」「ADIFを追加」、時刻の変換などのあと、画面の下に出る通知から、その前のログに戻せます(約 8 秒)。OK で day + などを入れたときも出ます
メニューの「元に戻す」ログを丸ごと置き換える前の内容を 1 つだけ覚えていて、あとからでも戻せます

予定

メニュー →「予定」。行き先を 50 件まで登録できます。項目は「前日: 準備する」の表のとおりです。

  • 「新しいログ」「場所の変更」の画面の「予定から選ぶ」で使います。予定の自局・山・公園・グリッド・備考#が欄に入り、書き込むと、予定の日付・リグ・QSL メッセージも指令の行になります(ログにすでに同じ行があれば書きません)。
  • 予定に入れた山頂の地図は、電波のあるところでアプリを開いたときと、予定を保存したときに、自動で端末に保存されます。一覧に「地図: 保存済み」か「まだ保存していません」が出ます。
  • 予定は同期の対象です。

場所の画面と備考#

備考は 2 通りに書きます。書く場所と、かかる範囲が違います。

mycall JA1ABC
mysota JA/ST-012
# JCC 1234 山の北側
40m cw
0900 ja1abc 59 {山田さん}
0905 ja2xyz 59
0910 ja3def 59 {ご近所}
備考#例の # JCC 1234 山の北側。行の先頭に # を書きます。これより後ろの全 QSOにかかります(例では 3 つとも)。JCC・JCG など、運用全体の覚え書きに使います
備考{}例の {山田さん}。QSO の行の中に {…} で書きます。その行の QSO だけにかかります(例では 0900 の ja1abc だけ)。相手の名前など、1 局ごとの覚え書きに使います

どちらも、SOTA・POTA・WWFF のファイルには入りません。HAMLOG の QTH・Rmks1・Rmks2 には、設定で選んで書けます。

「新しいログ」と「場所の変更」で開く画面です。自局のコールサイン・SOTA・POTA・WWFF・グリッド・備考#を入れて「ログに書き込む」と、指令の行(mycall・mysota など)を書きます。

  • SOTA・POTA・WWFF は、名前や番号を打つと候補が出ます(電波が要ります)。「地図」で山頂の地図を開けます。グリッドは「現在地」でも入ります。
  • 書式が正しくないときは、画面を閉じずに、欄の下に知らせます。
  • 備考#には JCC・JCG などを書きます。山・公園を候補から選ぶか、「現在地」で現在地を取ると、電波があれば JCC・JCG を調べて入れます *1)。手で書いた備考#は、書き換えません。
  • 備考#の欄が空のまま書き込むと、山(なければ最初の公園)から調べて書きます。調べられなければ書きません。
  • 開いたときの備考#の欄は、その位置で有効な備考#です。変えて書き込むと、新しい # の行を足します(前の備考#は消しません)。同じなら書きません。
  • 「新しいログ」では、バンド(または周波数)とモードも入れられます。指令の行のあと、最初の QSO の前に書きます。
  • 場所を書き込むと、自局のコールサインを覚え、次の「新しいログ」の初期値にします。

*1) 国土地理院のデータと、このアプリのサーバーで調べます。備考#は # で始まる行なので、出力のファイルには入りません(HAMLOG の欄には、設定で書けます)。

PC とスマホの同期

設定(設定の表で「する」のもの)と予定を、端末の間で同期します。ログの本文は同期しません。

  1. PC など、最初の端末: 歯車 →「設定・予定の同期」→「同期を始める(コードを作る)」。QR コードと、26 文字の同期コードが出ます。
  2. スマホ:
    • Android: カメラ(Google レンズなど)で QR を読み、開いた画面で「参加する」を押す。
    • iPhone: ホーム画面のアプリを開き、歯車 →「QRを読む」で QR を読むか、同期コードを入れて「参加」を押す *1)。
  • 参加すると、その端末の設定は、同期している設定で置き換わります。その端末の予定はそのまま残り、同期している予定と合わさります。ログの本文は変わりません。
  • 一度参加すれば、あとは開いたとき(電波のあるところ)に自動で同期します。山頂では電波がなくても、同期済みの予定がそのまま使えます。
  • やめたいときは「同期をやめる」(サーバーの設定・予定も消せます)。

Note: 同期コードを知っている人は、設定と予定を読み書きできます。QR やコードは、人に見せないでください。

*1) カメラアプリで読むと Safari で開くので、ホーム画面のアプリには反映されません。

山頂の地図

メニュー →「山頂の地図」(カーソルの位置で有効な山頂)か、予定・場所の画面の「地図」で開きます。

  • 山頂のアクティベーションゾーン、市区町村の境、市区町村ごとに該当する POTA の公園を出します。
  • 現在地(GPS)を地図に重ねます。地図の下には、いまいるところで当たる山頂・公園のコード(アクティベーションゾーンの中なら山頂のコード、公園の中ならその公園のコード)を緑で出します。境界の近く(GPS の誤差と、区域のデータのずれの範囲)では、言い切らずに橙で出します。ゾーンの外なら、山頂までの距離を出します。GPS の誤差も添えます。
  • その下に、交信で聞かれたときに読み上げられるよう、山頂のコード・山名・標高と、ゾーンにかかる市区町村ごとの JCC・JCG と、そこで当たる POTA の公園を並べます。いまいる市区町村には ▶ を付け、先頭に出します。
  • 「(一部)」と書いた公園は、その市区町村の中のゾーンの一部だけが公園です(地図の斜線の区域。一覧には同じ色の印が付きます)。
  • 予定に入れた山頂と、場所を書き込んだ山頂の地図は、電波があれば端末に保存され、電波がなくても見られます。
  • 通信するのは、アプリを開いたときと、地図を開く・場所を書き込む・予定を保存するときだけです。電波が戻っただけでは通信しません。地図の更新は、アプリを開いたときに確かめます。

書き出すファイル

zip の名前は、最初の QSO の日付・運用場所・書き出した時刻です(fle-20261019@JA-ST-012-JP-1151-1543.zip など)*1)。「FLEログを保存」も同じ名前で .txt です。

sotaYYYYMMDD.csvSOTA のログ(山の QSO。UTC の日付ごと)。S2S があれば sota-s2s-…csv も。自局の山・公園がないログでは、全 QSO のチェイス用の CSV(自局の山は空)
コールサイン@公園-日付.adiPOTA の ADIF(公園ごと。日をまたいでも 1 つで、日付は最初の QSO の日)。WWFF・SOTA(山ごと。名前の / は -)も同じ形。周波数を書いたときは FREQ、山があれば MY_SOTA_REF(自分)・SOTA_REF(相手)も入ります
adif-….adi全 QSO の ADIF(場所に関係なく 1 つ。名前は HAMLOG の CSV と同じ形)。山があれば MY_SOTA_REF・SOTA_REF も入ります(POTA・WWFF の SIG は入りません)
hamlog-….csvHAMLOG の取り込み用 CSV(時刻は設定の「HAMLOG の時刻」。QTH・Rmks1・Rmks2 は設定の「HAMLOG の出力」)
contest-日付.txtコンテストのログのときに作られる、ZLOG 形式のファイル
fle-日付@運用場所-時刻.txt元の FLE ログ。名前も中身も「FLEログを保存」と同じです
  • SOTA・POTA・WWFF のファイルは、いつも UTC です。
  • 誤りのある行があるときは、これらのファイルは作られず、誤りを書いたテキストと、元の FLE ログだけが入ります。
  • 日付・自局・運用場所が足りないとき、聞き取れなかった文字 ? のあるコールサインがあるときは、書き出しの前に確認の画面が出ます。

*1) 書き出すたびに別の名前になり、上書きされません。

FLE の書き方

ログは行単位です。空行は無視されます。# から行末までは備考#で、出力には入りません。

指令の行(現れた行から先が有効)

mycall JL1NIE/1自局のコールサイン
operator JL1NIE運用者(省略すると自局から)
mysota JA/KN-028自局の山。- で解除
mypota JP-0001 JP-0002自局の公園(重なる公園は並べる)。- で解除
mywwff JAFF-0001自局の WWFF
mygrid PM95uq自局のグリッド(4・6・8 文字)
date 2026-10-25日付(10/25 も可)。時刻は 00:00 に戻る
day + / day ++日付を 1 / 2 日進める(0 時をまたぐとき)。自動で入るときの動きは「0 時をまたぐとき」を見てください
timezone jst時刻の時間帯。jst、utc、+9 のような数字。省略すると UTC。ふつうは設定の「タイムゾーン」が先頭に書きます。ログの途中で変えると、直前の時刻を同じ瞬間のまま新しい時間帯で読み替えます(UTC 23:30 のあとの timezone jst は、翌日の 08:30 から続きます)

QSO の行

次の語を、順番を気にせず並べます。

時刻1〜4 桁の数字。1 桁=分の 1 の位、2 桁=分、3 桁=H:MM、4 桁=HH:MM。省いた上の桁は前の行から引き継ぐ
バンド40m 2m 70cm など。次のバンドまで続く
周波数7.030(MHz)。バンドも決まる
モードcw ssb fm am ft8 など。次のモードまで続く
コールサイン1 行に 1 つ。ここで QSO が 1 件できる。聞き取れなかった文字は ?(JA1AB?)
レポートコールサインのあとの数字。1 つなら送ったレポート、2 つなら送ったレポートと、もらったレポート。
省いた桁は、モードに合わせて補います(□ は打った数字)。
CW など: 1 桁=5□9(7→579)、2 桁=□□9(44→449)
SSB・FM・AM: 1 桁=5□(7→57)、2 桁=そのまま
3 桁は、どのモードでもそのまま。FT8 などは -18 のような SNR
相手の山・公園ja/st-012 か st-012(SOTA。アソシエーションを省けるのは、自分の山があるときだけ)、jp-1234(POTA)、jaff-0001(WWFF)
相手のグリッドpm85rl。コールサインの後ろに書く。HAMLOG の GL と、ADIF の GRIDSQUARE に入る
メッセージ<…> QSO メッセージ、[…] QSL メッセージ、{…} 備考{}(その QSO だけ)

文法の詳しい仕様は、docs/fle-grammar.md にあります。元になった FLE(Fast Log Entry)の考え方は、こちらの記事にあります。
