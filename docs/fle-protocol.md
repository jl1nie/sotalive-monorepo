# FLEonline: コアと画面のプロトコル

`crates/fle-core`(パーサ。今は手書き、のちに nom)と、`apps/fle`(画面)のあいだの取り決め。
コアは WASM(`crates/fle-wasm`)として画面から呼ぶ。

## 原則

1. **ログのテキストが唯一の正。** 補完した結果は、テキストに書き込んで残す。
   開き直しても、再解釈しても、同じ結果になる。
2. **コアは純粋。** 時計も保存先も持たない。「いまの時刻」などは引数で受け取る。
3. **位置は UTF-16 の文字位置**(JS の文字列の添字)で受け渡す。コアの内部は UTF-8 なので、境界で変換する。
   日本語・絵文字を含むテキストでも位置がずれない。行番号は `\n` 区切りの 0 始まり。
4. **コアの関数は状態を持たない。** 同じ入力は同じ出力。

## 関数

| 関数 | 入力 | 出力 | 画面が呼ぶとき |
|---|---|---|---|
| `compile(text)` | テキスト全体 | QSO とエラー(行番号つき) | 入力のたび |
| `complete(textBeforeCaret)` | カーソルより前のテキスト | 文法上ありえるキーワードの候補 | 入力・カーソル移動のたび |
| `fill(text, line, nowMs, defaultTz)` | テキスト全体、行、いまの時刻、既定のタイムゾーン | 直す箇所 `Edit[]` | Enter |
| `generateZip(text, nowMs)` | テキスト全体、いまの時刻 | ZIP | 生成ボタン |

### `complete`
- 返すのは**キーワードだけ**(コマンド、バンド、モード、`day` の `+` / `++`)。
- 候補の元は、パーサが使う表。キーワードを足せば補完にも出る(将来 nom では、文法が期待するキーワードの集合から導く)。
- 行頭は1文字以上打ってから。2語目以降は、文法が絞っているので、何も打たなくても返す。
- 並びはコアが決める(同じ入力なら同じ並び)。画面は並べ替えない。

### `fill` — 補完をテキストに確定する
`Edit` は `{ from, to, insert }`。位置は渡したテキストに対するもので、互いに重ならない。
**後ろの位置のものから順に**適用する。返される修正がなければ空。**冪等**(適用後に再び呼ぶと空)。

v1 で確定するもの:
- **時刻のない QSO 行**(コールサインから始まる行)の行頭に、`HHMM ` を挿入する。
  `ja1xyz` → `0905 ja1xyz`。すでに時刻のある行(`0900 ja1xyz`、分だけの `4 ja4qru`)、設定行、空行は対象外。

#### 時刻の書式(タイムゾーン)
基本は **UTC**。

1. ログに `timezone +9` などの指定が(その行より前に)あれば、その時間帯で書く。
2. なければ UTC。ただし、設定の既定のタイムゾーンが UTC 以外で、**ログにまだ QSO が1つもない**ときは、
   `timezone +N` の行をテキストの先頭に挿入し、その時間帯で書く(ログが自己完結する)。
3. すでに QSO があるのに `timezone` の指定がないログでは、それまでの時刻は UTC の意味なので、
   **設定が UTC 以外でも UTC で書く**(途中で意味を変えない)。

先頭行の行頭に両方が入るときは、同じ位置に2つ入れず、1つの修正にまとめる。
真夜中をまたぐ場合は、時間帯の時差を足してから時刻を書く。

## 画面側の約束

- **確定は Enter。** 行末にカーソルがあるときに、`fill` を呼び、修正を適用してから改行する。
  修正がなければ、ふつうの改行。行の途中の Enter(行を分けるだけ)や、IME の変換中は、呼ばない。
- **時刻は「その行を打ち始めた時刻」。** 行の最初の1文字を打った時刻を覚えて、`nowMs` として渡す。
  コールサインを打つのに時間がかかっても、交信の開始に近い時刻になる。覚えていなければ、Enter の時刻。
- 修正の適用後、カーソルは「挿入位置より前に入った文字数」だけ進める(`mapCaret`)。
- 設定の既定のタイムゾーンは、`defaultTz` として渡す(UTC は 0、整数の時間差)。

## 型について
画面側の型(`apps/fle/src/lib/fle.ts`、`edits.ts`)は、いまは手で書いている。
コアの出力の形と食い違わないよう、`tsify` で Rust の型から生成する案がある(未実施)。

## nom 化したときに変わらないもの
上の関数の入出力と、`crates/fle-core` のテスト(特に `fill` の冪等性・UTF-16 の位置・タイムゾーンの規則)は、
文法を nom に置き換えても変えない。内部では、構文木の各要素が元のテキストの位置(span)を持つので、
`fill` の挿入位置は、そこから求める。
