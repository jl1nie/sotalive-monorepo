# FLEonline: コアと画面のプロトコル

`crates/fle-core`(パーサ。今は手書き、のちに nom)と、`apps/fle`(画面)のあいだの取り決め。
コアは WASM(`crates/fle-wasm`)として画面から呼ぶ。

## 責務の分担(崩さない)

**文法はコア(`fle-core`、のちに nom)。動作は PWA(`apps/fle`)。**

| | コア(文法) | 画面(PWA の動作) |
|---|---|---|
| 持つもの | FLE の文法のすべて: 解釈、エラー、補完(どこからが入力中の語か・次に来るキーワード)、確定(`fill`)、ADIF → FLE の変換、見本のログ、出力ファイルの書式 | 入力のイベント、保存(localStorage)、Service Worker とキャッシュ、時計、設定、画面 |
| 持たないもの | 時計、保存先、ネットワーク、DOM | キーワード、語の区切り、書式など、文法の知識 |

迷ったときの基準:
- **文法が変わったら直すことになるか?** → コア(テストで保証する)。
- **端末・ブラウザ・時間に依存するか?** → 画面。コアには引数で渡す(例: `now`、`defaultTz`)。

## 原則

1. **ログのテキストが唯一の正。** 補完した結果は、テキストに書き込んで残す。
   開き直しても、再解釈しても、同じ結果になる。
2. **コアは純粋。** 時計も保存先も持たない。「いまの時刻」などは引数で受け取る。
3. **位置は UTF-16 の文字位置**(JS の文字列の添字)で受け渡す。コアの内部は UTF-8 なので、境界で変換する。
   日本語・絵文字を含むテキストでも位置がずれない。行番号は `\n` 区切りの 0 始まり。
4. **コアの関数は状態を持たない。** 同じ入力は同じ出力。

## 関数

| 関数 | 入力 | 出力 | 画面が呼ぶとき |
|---|---|---|---|
| `compile(text)` | テキスト全体 | QSO とエラー(行番号つき) | 入力のたび |
| `complete(textBeforeCaret)` | カーソルより前のテキスト | 候補(キーワード)と、確定で置き換える範囲の開始位置 `from` | 入力・カーソル移動のたび |
| `checkOutput(text)` | テキスト全体 | 出力前の警告 `OutputWarning[]`(足りない情報) | 「生成」を押したとき |
| `stationAt(text, line)` | テキスト全体、行 | その行の直前までで有効な自局と運用場所 | 「新しいログ・場所」シートを開くとき(初期値) |
| `stationPlan(text, line, want)` | テキスト全体、行、書きたい自局・場所 | 書き込む修正 `edits` と、項目ごとの誤り `errors` | シートで「ログに書き込む」 |
| `gridLocator(lat, lon)` | 緯度・経度 | グリッドロケータ(6文字)。範囲外は `undefined` | シートの「現在地」 |
| `adifToFle(adif)` | ADIFのテキスト | FLEのテキスト | ADIFを追加するとき |
| `sampleLog(date)` | 日付(`YYYY-MM-DD`) | 見本のFLEログ | 見本を入れるとき |
| `fill(text, line, nowMs, defaultTz, options?)` | テキスト全体、行、いまの時刻、既定のタイムゾーン、確定の範囲(省略可) | 直す箇所 `Edit[]` | Enter(`options` なし)、確定ボタン(設定に従う) |
| `generateZip(text, nowMs)` | テキスト全体、いまの時刻 | ZIP | 生成ボタン |

### `complete`
- 返すのは**キーワードだけ**(コマンド、バンド、モード、`day` の `+` / `++`)。
- 候補の元は、パーサが使う表。キーワードを足せば補完にも出る(将来 nom では、文法が期待するキーワードの集合から導く)。
- 行頭は1文字以上打ってから。2語目以降は、文法が絞っているので、何も打たなくても返す。
- **設定行(`40m cw`)は、バンド(周波数)とモードが順不同**。片方を書いたら、改行せずにもう片方を返す(両方そろったら返さない)。
- よく使うモード・バンドを先に並べる(cw, ssb, fm, … / 40m, 20m, 80m, …)。
- **`from` は、置き換える範囲の開始位置**(終わりはカーソル)。「どこからが入力中の語か」は文法の知識なので、画面は語の区切りを知らない。
- 並びはコアが決める(同じ入力なら同じ並び)。画面は並べ替えない。

### `fill` — 補完をテキストに確定する
`Edit` は `{ from, to, insert }`。位置は渡したテキストに対するもので、互いに重ならない。
**後ろの位置のものから順に**適用する。返される修正がなければ空。**冪等**(適用後に再び呼ぶと空)。

**時刻の挿入は常に行う**(「いま」はあとから再現できない、テキストに残らない情報だから)。
時刻のない QSO 行(コールサインから始まる行)の行頭に `HHMM ` を入れる(`ja1xyz` → `0905 ja1xyz`)。
それ以外に何を確定するかは、`options` の3つの指定で、**独立に**選ぶ(すべて省略可、省略は偽)。

| 指定 | 確定するもの |
|---|---|
| `expandTime` | 省略形の時刻(`15` 分だけ、`115` H:MM)を、前の行から決まる `HHMM` に置き換える |
| `bandMode` | 省略されたバンド・モードを、コールサインの前に挿入する(`40m CW `)。周波数で指定されたログ(`7.025 cw`)では、バンドでなく周波数を入れる(バンドを入れると周波数が既定値に戻るため) |
| `rst` | 省略された RST を、コールサインの直後に、モード既定の値(CW `599`、SSB/FM `59`、デジタル `-10`)で挿入する。省略形は解決した値に置き換える(`4` → `549`、`6 7` → `569 579`) |

- Enter は `options` なし(時刻の挿入だけ)。確定ボタンは、設定の「確定の書き方」に従う(時刻の展開は常に。RST は既定で書く、バンド・モードは既定で書かない)。
- **省略しても意味は同じ**(FLE では、省略した RST は既定値、バンド・モードは前の設定行から引き継ぐ)。だから、どこまで書くかは利用者が選べる。
  画面の候補バーは、書く範囲に関わらず、いつも**完全な解釈**を見せる。

守る性質:
- **確定しても、解釈は変わらない。** コール・バンド・周波数・モード・RST・リファレンス・コメントは、確定の前後で同じ(3つの指定の全組み合わせでテストして保証)。
- **冪等。** 適用した後に再び呼ぶと空(全組み合わせでテスト)。
- 解釈の結果が要る指定(`expandTime` / `bandMode` / `rst`)では、**エラーのある行・QSO でない行は何も変えない**(空を返す)。
- **利用者が書いたもの(リファレンス、コメントなど)は動かさず、足りない部分を挿入し、省略形だけを置き換える。**
- RST は、コンパイラと同じく、コメントを読み飛ばして、コールサイン直後の数値/SNR を読む。

#### 時刻の書式(タイムゾーン)
基本は **UTC**。

1. ログに `timezone +9` などの指定が(その行より前に)あれば、その時間帯で書く。
2. なければ UTC。ただし、設定の既定のタイムゾーンが UTC 以外で、**ログにまだ QSO が1つもない**ときは、
   `timezone +N` の行をテキストの先頭に挿入し、その時間帯で書く(ログが自己完結する)。
3. すでに QSO があるのに `timezone` の指定がないログでは、それまでの時刻は UTC の意味なので、
   **設定が UTC 以外でも UTC で書く**(途中で意味を変えない)。

同じ位置への挿入(先頭の `timezone` 行と時刻、時刻とバンド・モードなど)は、1つの修正にまとめる。
真夜中をまたぐ場合は、時間帯の時差を足してから時刻を書く。

### 自局と運用場所(mycall / mysota / mypota / mywwff / mygrid)
自局のコールサインと運用場所は、`timezone` と同じく**ログのテキストに書く**(ログ1つで完結し、一元管理できる)。

- **すべて任意。** 指定がなければ何も反映しない。**現れた行以降が有効**で、あとの指定が前の指定を**置き換える**。
  だから、1つのログに複数の場所(1日に複数の山・公園)を書ける。
- `mypota` は、行に並べた公園が「そのときの運用場所のすべて」(`mypota JA-0001 JA-0002`)。
  以前は行ごとに**追加**されていたが、場所を変えると前の公園が残るため、置き換えにした。
- **`-` で解除する**(`mysota -`、`mypota -`、`mywwff -`、`mygrid -`)。自局のコールサインは解除できない。
- `mygrid`: メイデンヘッド。4・6・8文字(`PM95`、`PM95uq`、`PM95uq12`)。書き方は `PM95uq` にそろえる。
- 各QSOの記録は、そのときの自局・場所を持つ。ADIF には `STATION_CALLSIGN` と `MY_GRIDSQUARE` が出る。

**出力ファイルは、運用場所 × UTC の日付ごとに分ける。**
- POTA / WWFF の ADIF: `{自局}@{リファレンス}-{日付}.adi`。その場所・その日の QSO だけ。
  同じ場所の複数の公園には、同じ QSO を、それぞれのファイルに入れる。
- SOTA の CSV: 日付ごと(`sota{日付}.csv`)。山にいるときの QSO だけ(行ごとに、そのときの山)。
- HAMLOG / AirHam の CSV: ログ全体を1つ。ファイル名には、ログに現れた場所を、現れた順にすべて入れる。

**`stationPlan` — 場所を指令の行にする**
- 現在の値(`stationAt`)と違う**項目だけ**を書く(同じなら何も書かない。冪等)。空にする項目は `-`。
- `line` の行の**前**に挿入する。カーソル位置の文脈で、その行以降に有効になる。
  ログの先頭(新しいログ)でも、途中(場所の変更)でも、同じ仕組み。
- 入力は、空白・カンマ区切りを許し、大文字にそろえる。書式の誤りは、書き込まずに項目ごとに返す。
- 指令の書式は文法の知識なので、**書式を決めるのはコア**。画面は入力欄と、位置情報の取得だけ。

画面側(PWA の動作): 「新しいログ・場所を設定」シートは、開くとき `stationAt(カーソルの行)` を初期値にする。
自局のコールサインが空なら、**前回のコールサイン**(ログに `mycall` が現れるたびに覚える)を初期値にする。
`/1` などの移動の表記を付けられるよう、編集できる。

### 出力前の警告(`checkOutput`)
ファイルを生成する前に、ログに足りない情報を調べる。**何が足りないと、どの出力に影響するか**は出力の知識なので、判定はコアが行う。
返すのは、文面ではなく、**コード + 項目 + 重さ + 影響するQSOの数**(文面は画面が、言語設定で作る)。

| コード | 項目 | 重さ | 条件 | 影響 |
|---|---|---|---|---|
| `missing_mycall` | `mycall` | 必須 | 自局のコールサインのないQSOがある | ADIF の `STATION_CALLSIGN`、SOTA CSV の自局が空になる |
| `missing_place` | `place` | 推奨 | どのQSOにも、運用場所(SOTA・POTA・WWFF)がない | POTA・WWFF の ADIF は作られない |
| `missing_grid` | `grid` | 推奨 | ADIF に入るQSO(POTA・WWFF)に、グリッドがない | ADIF の `MY_GRIDSQUARE` が出ない(SOTA の CSV には列がないので対象外) |

- 誤りのあるログ(誤りの記録だけを出す)と、QSOのないログは、何も返さない。
- 順序は固定(`missing_mycall`、`missing_place`、`missing_grid`)。
- **画面の約束**: 「生成」で、警告があれば確認のシートを開く(なければ、そのまま生成)。シートは、足りない項目の入力欄だけを出す
  (自局のコールサインは前回のものが初期値、グリッドは「現在地」で求められる。運用場所は、場所のシートへ誘導する)。
  操作は「ログに書き込んで生成」(`stationPlan(text, 0, …)` で、ログの先頭に指令を書いてから生成)、「このまま生成」、「閉じる」。
  足りなくても、生成は止めない(警告)。

### 山・公園の候補(PWA の動作。コアの外)
場所のシートで、SOTA の山・POTA の公園を、sotaapp2 のバックエンドから探して、候補に出す。
**ネットワークで引くのは画面の役目**で、コアは関与しない(コアは純粋なまま、オフラインでも動く)。
選んだコードの書式は、これまでどおり、書き込むときに `stationPlan` が検証する。

- **登る前にオンラインで場所を入れておく前提。オフラインなら候補は出さない**(手入力はできる)。
  履歴・端末への保存・API 応答のキャッシュは作らない(必要になったら足す)。
- API(同じオリジンの `/api` 中継): `/api/v2/sota/summits/search`、`/api/v2/pota/parks/search`。
  `name` は、コードと日本語・英語の名前への**部分一致**(`JA/TK-0`、`JP-01`、`高尾`)。
  種類別の API を使う(統合の `search/full` は、片方の条件だけを渡すと、もう片方が絞られない)。
- 入力中の候補: 2文字以上、300ms 待って問い合わせ、次の入力で前の検索を中止する。
  POTA の欄は、空白・カンマで区切った**最後の語**で探す。
- 候補を選ぶと、山は SOTA の欄に、公園は入力中の語を置き換えて POTA の欄に入る。
  公園には**対応する WWFF**(`JP-0117` ↔ `JAFF-0049`)があり、WWFF の欄が空なら入れる。
  グリッドも、空なら候補のものを入れる。どれも、あとから編集できる。
- 「現在地」: グリッドを入れ(コアの `gridLocator`)、**近くの山・公園**を距離順に並べる(3km、なければ10km)。
  バックエンドの「中心と距離」(`dist`)の検索は、単位の不具合で使えない
  ([sotaapp2#11](https://github.com/jl1nie/sotaapp2/issues/11))ので、**範囲(`min_lat` など)で探し、距離は画面で求める**。

### `compile` が返す QSO の時刻
`time` は UTC(`HH:MM`)。`tz`(そのQSOの時間差)と `localTime`(ログに書かれている形の時刻)も返す。
画面は、UTC 以外のときは `localTime` に時間帯を添えて見せる(例: `18:05 (UTC+9)`)。
タイムゾーンの指定は、その行以降の QSO に有効(途中で変えられる)。

## 画面側の約束

- **Enter は、時刻だけ確定する。** 行末で改行が入ったときに `fill`(`options` なし)を呼び、修正を適用する。
  修正がなければ、ふつうの改行。行の途中の改行(行を分けるだけ)、IME の変換中、複数文字の貼り付けでは呼ばない。
  キーの種類(keydown)でなく、**テキストの変化**(行末に改行が1つ入った)で判定する。
  ソフトキーボードは keydown を送らないことがあるため。
- **緑の候補バーは、確定ボタン。** 解釈できた行(エラーなし)で、バーを押すと、設定に従う範囲で `fill` を適用し、
  行末に改行を入れて次の行へ進む。押してもテキスト入力のフォーカスは奪わない(キーボードを閉じない)。
  バーには、**完全な解釈**(時刻・バンド・モード・RST)を、書く範囲に関わらず、先に見せる。
  エラーのある行では、ボタンにならない(黄色の「入力中…」)。
- **時刻は「その行を打ち始めた時刻」。** 行の最初の1文字を打った時刻を覚えて、`nowMs` として渡す。
  コールサインを打つのに時間がかかっても、交信の開始に近い時刻になる。覚えていなければ、確定の時刻。
- 修正の適用後、カーソルは「挿入位置より前に入った文字数」だけ進める(`mapCaret`)。
- 設定の既定のタイムゾーンは、`defaultTz` として渡す(UTC は 0、整数の時間差)。

## 型について
画面側の型(`apps/fle/src/lib/fle.ts`、`edits.ts`)は、いまは手で書いている。
コアの出力の形と食い違わないよう、`tsify` で Rust の型から生成する案がある(未実施)。

## nom 化したときに変わらないもの
上の関数の入出力と、`crates/fle-core` のテスト(特に `fill` の冪等性・「確定しても解釈は変わらない」・UTF-16 の位置・タイムゾーンの規則)は、
文法を nom に置き換えても変えない。内部では、構文木の各要素が元のテキストの位置(span)を持つので、
`fill` の挿入位置は、そこから求める。
