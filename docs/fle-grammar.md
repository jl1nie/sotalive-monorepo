# FLE の文法: 現行の書き起こしと、nom 化のレビュー

`crates/fle-core` の文法(`tokenizer.rs`・`compiler.rs`)を、仕様として書き起こし、実測で見つかった問題と、nom での書き直しの設計案をまとめる。
レビューで決めたことは、末尾の「決めること」に記録する。

前提(`docs/fle-protocol.md`):
- コアの入出力(`compile` / `complete` / `fill` / `stationAt` など)と、`fle-core` のテストは、nom 化しても変えない。変えるのは中身だけ。
- 文法はコア(nom)、動作は PWA。文法の知識は、画面に漏らさない。

## 1. 現行の文法

### 1.1 行の種類
ログは行単位。行は次のどれか(上から順に判定)。

1. 空行(空白だけ)→ 何もしない。
2. **指令の行**: 先頭の語がキーワード(下表)で、その処理が `Handled` になるもの。
3. **QSOの行**: それ以外(設定の行 `40m cw` も、QSOの行 `0900 ja1xyz` も、同じ経路で処理される)。

`#` から行末までは注釈。ただし語の途中でも、`#` `<` `[` `{` で語が切れる。

### 1.2 字句(1語の分類)
語は空白(半角、全角 U+3000)で区切る。**タブは空白ではない**。語は、次の順で最初に当てはまるものに分類される(位置に関係なく、同じ語は同じ分類)。

| 順 | 分類 | 規則 |
|---|---|---|
| 1 | 日付 | `\d+[/-]\d+[/-]\d+`(年月日)、`\d+[/-]\d+`(月日) |
| 2 | 周波数 | `\d+\.\d+` |
| 3 | SNR | `[+-]\d+` |
| 4 | バンド | バンド名の表(`160m` `40m` `70cm` など)。大文字小文字は区別しない |
| 5 | WWFF | `\w+FF-\d+` |
| 6 | SOTA | `\w+/\w+-\d+` |
| 7 | POTA | `\w+-\d+`(WWFF でないもの) |
| 8 | キーワード | 指令の表(下表) |
| 9 | モード | モードの表(`cw` `ssb` `ft8` など) |
| 10 | 数値 | `\d+`(桁数を持つ) |
| 11 | コールサイン | `[A-Z]{1,3}[0-9][A-Z0-9]*[A-Z]`、または `/` で区切った部分のどれかがそれに合うもの |
| 12 | コンテスト送信 / 受信番号 | `.XXX` / `,XXX` |
| 13 | 不明 | `/` か `-` を含む、上のどれでもない語 |
| 14 | リテラル | それ以外(**大文字にされる**) |

括弧の注釈: `<…>`(QSOメッセージ)、`[…]`(QSLメッセージ)、`{…}`(備考)。同じ種類が複数あれば、あとのものが残る。閉じていなければ、行末までが注釈になる(誤りにならない)。

### 1.3 指令

| 指令 | 値 | 効果 |
|---|---|---|
| `mycall` | コールサイン | 自局。**`operator` も、ポータブルを除いたコールサインにする** |
| `operator` | コールサイン | 運用者 |
| `mysota` | SOTA 参照、または `-` | 自局の山(`-` で解除) |
| `mywwff` | WWFF 参照、または `-` | 自局の WWFF |
| `mypota` | POTA 参照を1つ以上、または `-` | 自局の公園(**置き換え**) |
| `mygrid` | グリッド、または `-` | 自局のグリッド(4・6・8文字、`PM95uq` にそろえる) |
| `date` | 年月日 / 月日 | 基準日付。時刻を 00:00 に戻す |
| `day` | `+` / `++` | 日付を 1 / 2 日進める。時刻を 00:00 に戻す |
| `timezone` | `+N` / `-N`(符号つき整数) | 以降の時刻の時間帯 |
| `rigset` | 数値 | リグの番号 |
| `nickname` | 任意の語 | ニックネーム |
| `number` | `consecutive`、または任意の語 | コンテストの番号の付け方 |
| `qslmsg` / `qslmsg2` | 行の残り | QSLメッセージ。`$mywwff` `$mysota` `$mypota` を、**その指令の時点の値**で置き換える |

運用場所(`mysota` `mypota` `mywwff` `mygrid`)・自局・時間帯は、**現れた行以降が有効**で、各QSOの記録に、そのときの値が入る。

### 1.4 QSOの行(状態機械)
語を左から順に処理する。状態は `Norm` / `Freq` / `RstSent` / `RstRcvd`。注釈は、どの状態でも読み飛ばして処理する。

- **Norm**(通常): 次を、**順不同・何個でも**受け付ける。
  - モード → モードを更新。
  - バンド → バンドを更新し、周波数をバンドの既定値に。次の状態は `Freq`。
  - 周波数 → 周波数を更新し、バンドを求める(範囲外は「Unknown band.」)。
  - 数値 → 時刻の更新(下記)。
  - コールサイン → 1行に1つ(2つ目は誤り)。バンドも周波数もなければ誤り。RST を既定値(モード別)にして、`RstSent` へ。
  - WWFF / SOTA / POTA の参照 → 相手局の参照。
  - コンテスト番号、リテラル、不明な語(誤り)。**リテラルは、1語をメッセージに、直後がリテラルならその語を備考にし、これを繰り返す。あとの語が前の語を上書きする**(下表 H)。
  - **それ以外(指令の語など)は、黙って無視する。**
- **Freq**: 次の語が周波数なら、周波数を更新。そうでなければ `Norm` に戻る(その語は消費しない)。
- **RstSent / RstRcvd**: 次の語(注釈を除く)が数値かSNRなら、送信 / 受信の RST。そうでなければ `Norm` に戻る(その語は消費しない)。
- 行の最後に、**コールサインがあればQSOの記録を作る。なければ何も作らない**(誤りも出さない)。

**時刻**(数値の桁数で決まる): 1桁=分の1の位、2桁=分、3桁=H:MM(時の1の位)、4桁=HH:MM、**5桁以上は黙って無視**。
時刻は、前の行から引き継ぐ(`date` / `day` で 00:00 に戻る)。**分が戻っても、時は進まない**(`0955` の次の `05` は `09:05`)。

**RST**: 桁数で決まる。1桁=`5` + 数 + `9`、2桁=RS、3桁=RST。省略時はモード別の既定値(CW `599`、SSB/FM/AM `59`、デジタル `-10`)。

### 1.5 状態(行をまたいで引き継がれるもの)
自局・運用者・運用場所・時間帯・基準日付・リグ・コンテスト番号・QSLメッセージ、そして **バンド・周波数・モード・時刻**。RST は、コールサインごとに既定値に戻る。

### 1.6 結果と誤り
- `status` は、誤りが1つでもあれば `ERR`。QSOの記録は、誤りがあっても出る。
- 誤りは `(行, 列, 英語のメッセージ)`。**列の意味が一定でない**(語の番号のことも、行内の文字位置のこともある)。
- 指令の誤りは、`Handled` と `Error` の2通りの戻りがあり、使い分けに一貫性がない。

## 2. 実測で見つかった問題

現行のコアで確かめた(`compile` の結果)。重大なものから。

| # | 問題 | 実測 |
|---|---|---|
| A | **数字で始まるコールサインが、QSOとして認識されず、誤りも出ずに捨てられる** | `7K1ABC` `8J1RL` `3B8CW` `9A1A` → QSO 0件、`status: OK`。`mycall 7K1ABC` は「Invalid callsign.」で、自局に設定できない |
| B | **タブ区切りの行が、黙って捨てられる** | `0900⇥ja1xyz` → QSO 0件、`status: OK` |
| C | コールサインのない QSO 風の行が、黙って捨てられる | `05 ja`(以前から既知) |
| D | 5桁以上の時刻が、黙って無視される | `09000 ja1xyz` → `00:00` |
| E | 年が桁あふれする日付が、黙って 2000 年になる | `date 99999-1-1` → 誤りなし |
| F | 分が戻っても時が進まない | `0955` → `05` が `09:05`(時刻が逆行) |
| G | 余分な値・位置違いのキーワード・値のない `qslmsg` を、黙って無視する | `mycall JA1ABC extra`、`0900 ja1xyz date`、行頭の `consecutive`、`qslmsg` |
| H | 平文の語が、大文字にされ、あとの語が前の語を上書きし、順序も入れ替わる | `hello world foo` → `FOO WORLD`、`hello world foo bar` → `FOO BAR`、`Hello {Remark} World` → `WORLD Remark`。括弧の注釈は大文字小文字を保つ |
| I | 括弧が閉じていないと、行末まで注釈になる(誤りなし) | `{abc` |
| J | バンドの大文字小文字が、入力のまま | `40M` → `40M`(`40m` と別の値になる) |
| K | 誤りの位置(列)の意味が一定でない / メッセージが英語のみ | 語の番号と文字位置が混在 |

A と B は、**データを失う不具合**。nom 化を待たず、現行の実装でも直す価値がある(テストを先に書く)。

## 3. nom での書き直しの設計案

### 3.1 構造: 構文木 → 評価の2段
- **構文(nom)**: 1行を、位置(span)つきの構文木にする。誤りがあっても、その行の誤りとして残し、ほかの行の解析を続ける(行単位で回復)。
- **評価**: 構文木を畳み込んで、状態(1.5)を更新し、QSOの記録・誤りを作る。構文と意味を分けるので、文法の変更とセマンティクスの変更が、互いに影響しない。

```text
行      = 空行 | 注釈行 | 指令 | QSO
指令    = キーワード 値…
QSO     = 要素*                      要素 = 時刻 | バンド | 周波数 | モード | コールサイン RST{0,2}
                                           | 参照 | コンテスト番号 | 注釈 | 平文
```

位置(span)は **UTF-16 の文字位置**で持つ(`fill` / `complete` の `Edit` と同じ座標)。これで、`fill` の挿入位置・誤りの位置・補完の置き換え範囲を、すべて構文木から求められる(いまは、`fill` が再トークン化して位置を換算している)。

### 3.2 補完: 期待キーワードの集合
- キーワードは、`kw("mysota", Kind::Command)` のように、**期待を記録する関数**を通して読む。
- エラー型を自作し、`alt` で複数の候補を試したときに、期待を**合算**する(標準の nom は、最後の1つしか残さない)。
- 「カーソルまでを読み切った位置(入力の終わり)で失敗した」ときだけ、その期待を候補にする(最も遠い失敗)。
- 文法に足したキーワードが、そのまま補完に出る(いまの表からの導出と同じ性質を保つ)。

### 3.3 誤りのコード化(多言語への備え)
誤りは、メッセージではなく、**コード + 引数 + span**で持つ(`MissingOperand { directive }`、`InvalidCallsign { word }` など)。メッセージの文面は、画面側が言語設定で作る。コアは、既定の英語の文面も返す(互換のため)。

### 3.4 互換と移行
- **バグ修正と文法の変更を分ける。** A・B は先に、現行の実装で直してテストを足す。nom 化では、その挙動を維持する。
- 「黙って無視する」ものを誤りにすると、**これまで通っていたログが、誤りになる**。どれを誤りにするかは、レビューで決める(3.5)。
- nom 版は、現行の実装と**同じ入力に同じ結果を返す**ことを、比較テストで確かめてから置き換える(誤りにすると決めたものだけが、差になる)。
